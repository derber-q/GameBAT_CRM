## Воспроизведённые дефекты

До исправления новые три регрессионных теста завершились `FAILED (failures=2, errors=1)`:

1. Фильтр `platform=<ID>` возвращал CD и Tech. Условие применялось только внутри
   ветки CD в `catalogue.visible_product_rows`. Теперь несовместимый вид товара исключается.
2. Запрос `игра & + кириллица` не находил `Игра & + Кириллица` на SQLite.
   Вместо `icontains` подключён существующий `catalog.product_search.filter_products_by_text`.
3. `price_min=NaN` приводил к необработанному `ValidationError` из DecimalField ORM.
   Теперь `CatalogueFilterForm` отклоняет NaN/Infinity, мусор, отрицательные цены,
   обратный диапазон и неверные ID; выдача сопровождается объяснением без HTTP 500.

Это воспроизведение через Django TestCase, **не** браузерная запись Network/Console.

## Контракт фильтров

- `q`, `category`, `platform`, `brand`, `product_type`, `price_min`, `price_max`, `sort`, `page`.
  Старый `kind=cd/tech` преобразуется в category.
- Несовместимые параметры очищаются при смене категории; сервер перенаправляет
  на согласованный URL и сбрасывает страницу. Формы не передают старый page.
- Цена — Decimal; принимаются точка, запятая и пробелы между разрядами.
- Фильтрация до пагинации, count по полной отфильтрованной выборке.
- Сортировки ограничены списком, имеют стабильные дополнительные ключи.
  «По дате добавления в новинки» использует `StorefrontProduct.created_at`;
  позиции без такого события идут после новинок по имени. ID не трактуется как дата.
- Карта категорий в `resource_storefront/filters.py` явно перечисляет точные типы CRM,
  получает их ID и фильтрует по FK. Поиск подстрок в названиях товаров не используется.
  Для изменения карты доступна настройка `RESOURCE_CATEGORY_TYPES`; при переименовании
  типов обновить карту. Не перечисленные типы остаются во «Всей технике».
- Все фильтры одиночные; OR внутри группы checkbox неприменим.
- Запросы — обычная навигация GET, без AJAX-гонок и бесконечного spinner.
  При сетевой ошибке работает стандартная страница ошибки/повтор браузера;
  отдельный экран сетевой ошибки приложения не добавлен.

Регрессии покрывают пересечение бренд/тип, CD/Tech, поиск со знаками и кириллицей,
валидные/невалидные границы цен, числовую сортировку, временную метку новинок,
пагинацию, нулевой остаток, отсутствие фильтров по недоступным товарам,
повторное добавление, реальные CMS-блоки, отсутствие черновиков у покупателя,
формат цен, рендер четырёх страниц без повреждения кодировки/повторов ID.
Существующие проверки допуска, отзыва, прав редактора и checkout также выполнены.
Back/Forward, реальная потеря сети, мобильная клавиатура и визуальный focus не проверены в браузере.

## Ассеты и эксплуатация

- Новые WebP: hero около 99 KB; четыре плитки — около 14–32 KB каждая.
  Производные просмотрены как локальные изображения. Фотографии товаров не заменялись.
- Оригиналы сохранены в `static/resource/artwork` и `static/resource/originals`.
  Пересборка: `.venv\\Scripts\\python.exe -m resource_storefront.asset_pipeline`.
- Manrope и Playfair Display обслуживаются локально из `static/resource/fonts`,
  вместе с SIL OFL. Источник файлов: официальный репозиторий Google Fonts,
  `ofl/manrope` и `ofl/playfairdisplay`. Загрузка в реальном браузере ещё не подтверждена.
- Версия CSS/JS в базовом шаблоне витрины повышена до 2.
- Схема и данные рабочей БД этой доработкой не изменялись; тесты использовали отдельную БД.
  Учётные сервисы и интеграционные worker не изменялись и не запускались для проверки.
- Перезапускается только локальный Django runserver после проверки команды процесса.
  Production-развёртывание, commit и push не выполнялись.
