# Внутренний стикер продажи

На странице любой продажи кнопка «Печать стикера» ставит задание на текущий
принтер этикеток через прежний Windows Print Agent / Local Agent. Статусы
продажи, касса, долг и физические остатки не меняются. Формат — один лист
58×40 мм, включая крупный цифровой номер, полный идентификатор и QR со ссылкой.
Нижний линейный штрихкод по просьбе владельца убран из новых этикеток.

На ранее напечатанных этикетках Code128 содержит точный `Sale.visible_id`,
например `SALE-000594`; эти коды продолжают работать. Общий сканер
CRM распознаёт этот префикс и URL из QR раньше обработчика товара и переводит на
защищённый маршрут `sales:scan`. Для Code128 поиск идёт по `visible_id`, для QR —
по ID из пути страницы. Внешний адрес не открывается: используется текущий адрес CRM.
URL другого сайта и другого порта тестовой CRM не перенаправляют к продаже.
Быстрый ввод сканера распознаётся также по физическим клавишам в русской раскладке;
поддержан старый ввод с точками вместо слешей. Сам QR содержит правильный URL,
его генератор не подменяет слеши точками. Старые стикеры перепечатывать не требуется.
При обычном вводе в текстовое поле перехода нет. Для обработчиков добавлены
необязательные параметры `registerGlobalBarcodeHandler(handler, {priority,
accepts})`; прежние вызовы сохраняют приоритет последнего зарегистрированного.

QR содержит абсолютную ссылку страницы продажи на том адресе, с которого
запрошена печать. Ссылку на `127.0.0.1` другой компьютер или телефон не откроет:
для межустройственного использования печатать из CRM, открытой по её LAN/публичному
адресу. QR не содержит сессионных ключей; вход и право `sales.view_sale_detail`
обязательны для печати, состояния задания и открытия продажи.

Состояние хранится в отдельной `SaleLabelPrintJob`; файлы — в `MEDIA_ROOT/sale_labels/`.
Исполнитель и агент используют общий файловый протокол с прежними стикерами
Avito. Результаты Windows привязаны к request UUID, claim и SHA-256. Повтор
HTTP-запроса с тем же ключом возвращает прежнее задание; незавершённая печать
этой продажи не дублируется. `uncertain` сохраняется для проверки сотрудником
и не перепечатывается автоматически. После проверки ошибки или подтверждённого
`done` новое ручное нажатие может создать следующий экземпляр.

Маршруты: POST `/<sale>/label/print/`, GET `/<sale>/label/print/<request UUID>/`,
GET `/by-barcode/?code=SALE-…` внутри `/crm/sales/`. CSRF сохранён. GET не создаёт
задание печати. Для просмотра отменённой/завершённой продажи действует тот же
контроль доступа; эти статусы не препятствуют печати внутреннего номера.

Миграция `sales.0040` добавляет только таблицу заданий; Windows-клиент использует
прежние маршруты агента, его переустановка не требуется. Перед применением
сохранить согласованную SQLite-копию в Docker. После загрузки кода перезапустить
web и обработчики, затем проверить `check_worker_health`.

Будущие регрессии (не запускались при внедрении по просьбе владельца):
`sales.test_sale_labels`, `core/test_sale_barcode_js.cjs`, прежние
`sales.test_avito_orders`, `sales.test_print_agents` и проверки сканера.
Макет отдельно растеризован при 203 dpi: QR декодирован, номер
визуально проверен. Это не подтверждение физического выхода бумаги из принтера.
