# Закупочная цена поставщика внутри рейса

Задание 22.10.2026: редактировать цену AED конкретной строки поставщика, сохраняя согласованные рублёвые цены покупателей, количества, распределения и проведённую историю.

| Часть | Источник истины | Проверяемый результат |
| --- | --- | --- |
| Закупочная цена | `SupplierOrderBatchLine.supplier_price_aed_snapshot` | Изменяется только выбранная строка рейса, все её распределённые единицы |
| Согласованная выручка | Снимки цен `CustomerProcurementOrderItem` | Цены, суммы и наценки не переписываются |
| Курс и доставка | Связанная строка сохранённого прайса | Каждый заказ использует свой исторический курс и сохранённые расходы |
| Пересчёт | Распределения `SupplierTripAllocation` | Затраты и ожидаемая прибыль читаются из актуальной закупки без изменения выручки |
| Передача на склад | `receive_stock_order` → `accept_supply(defer_balance=True)` | Исправленная база плюс сохранённая доставка поступают в штатную проверку цен |
| Запрет изменений | Фактическая связь `order.supply_id`, завершение заказа | Проведённые товары и частично переданная общая строка недоступны для изменения |
| Аудит и конкуренция | `SupplierTripChange`, `batch.revision`, транзакция | Нет потери правок, повтор не меняет затраты повторно |

Сервисы: `orders/trip_prices.py`, HTTP — `trip_price_views.py`, общие блокировки старых форм — `order_editing.py`. Предпросмотр и сохранение выполняются POST с CSRF и действующими правами редактирования рейса: `orders.generate_supplier_orders`, `orders.edit_created_order`, `partners.view_supplier_details`, `price.view_supplier_prices`. Без права цен история корректировок с суммами скрыта. На просмотре заказа и рейса показаны текущие затраты и ожидаемая прибыль. Финансовые суммы в браузере не рассчитываются: он отображает строки из серверного Decimal-расчёта.

Причина изменения необязательна: пустое поле не препятствует сохранению и остаётся пустым в аудите. В таблице каждого поставщика техника упорядочена по типам, диски — по платформам, с заголовками групп. Внутри группы используется сохранённое название товара; для Nintendo Switch 2 и Nintendo Switch сохранён общий порядок CRM со вторым поколением первым. Сортировка не объединяет самостоятельные строки и не изменяет их данные.

Миграция `orders.0005_trip_supplier_price` добавляет `supplier_price_updated_at`. Это признак явной корректировки, а не второй источник цены. Сама AED-цена остаётся в существующем `supplier_price_aed_snapshot`. Все значения до/после, курсы, количества, рублёвые итоги и причина сохраняются в `SupplierTripChange.details`; каждая корректировка увеличивает ревизию. Повтор той же цены ничего не добавляет, устаревшая другая цена отклоняется. При переносе в пустой рейс признак сохраняется, несовместимые самостоятельные партии не объединяются.

Цена AED проверяется с точностью 6 знаков, деньги — по правилам `price.services.decimal_value`. Нулевая цена отклоняется в соответствии с существующим положительным ограничением `ProcurementSupplierOffer` и исходных поставщицких цен; отрицательные и нечисловые значения тоже недопустимы. Отрицательная ожидаемая прибыль допустима. База RUB округляется до копеек за единицу, затем добавляется сохранённая доставка и умножается на соответствующее количество. У предоплаты и постоплаты остаются собственные согласованные цены.

В новых Excel рейса, поставщика и состава заказа по поставщикам используется актуальная AED-цена строки. Покупательский Excel сохраняет цены заказа. Складской Excel после явной корректировки выводит исправленную закупку, разделяя цены разных партий, а не усредняя их.

В текущей архитектуре покупательский закупочный заказ завершается кассовыми проводками и не создаёт Sale; связи заказа с Sale нет. Новый механизм переноса в Sale не добавляется. Для этих заказов границей проведённой истории служит завершение заказа, для складских — фактическая связь с Supply, независимо от текстового статуса. Независимые строки других заказов не блокируются новой корректировкой.

Действующий механизм переноса между поставщиками сохраняет первоначальную базу складского заказа. Для совместимости явная корректировка AED отмечается в строке временем изменения: только она включает передачу исправленной базы в Supply. Само изменение покупательских цен или прайса не вызывается. История каждой корректировки сохраняется в существующем аудите рейса.

Недостающий исторический курс восстанавливается только из снимка той же версии прайса, включая сохранённую пару USDT/AED и USDT/RUB. Текущие биржевые данные не используются. Если достоверных значений нет, сохранение цены блокируется с понятной ошибкой.

Проверки должны охватить клиентов и склад в одной строке, нескольких поставщиков и курсы, расходы, убыток, пропавший курс, откат, права/CSRF, устаревшую форму, повторный запрос, конкурентную передачу в приход, Excel и сохранение этапа проверки цен Supply. Рабочие товары и заказы используются только для чтения; тестовые операции выполняются в отдельной БД. Коммит/push отдельно не запрошены.
