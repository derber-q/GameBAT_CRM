# ADR-0001: Устойчивые цифровые закупки поверх прежнего денежного журнала

Дата: 13.11.2026. Статус: принято в коде, реальные закупки включаются отдельно.

## Контекст

Существуют цифровые покупатели с общим балансом, Telegram-импорт чек-листов,
снимки себестоимости Sale, персональные прайсы и пассивный DigitalBot.
Удалённый заказ может выполниться после потери HTTP-ответа; частичное выполнение
не является единой атомарной операцией. SQLite не поддерживает блокировку
строки только через select_for_update. Покупателям нельзя раскрывать поставщика.

## Решение

Единый адаптер v2 и общий лимит в SQLite; отдельное приложение digital_shop
для намерений и резервов, но прежний BalanceMovement для денег. До POST
фиксируются ID, шифрованное неизменяемое тело и резерв. Длительная сеть не
удерживает транзакцию. Обязанность перед поставщиком и проведение покупателя
разделяются; результат и сумма клиента проверяются до завершения Sale.

Публичные сообщения собираются из разрешённых структур. Закупочный ответ
не становится сообщением покупателю. Неоднозначная выдача не повторяется сама.
Повторная доставка — отдельное явное действие сотрудника с аудитом.

## Рассмотренные альтернативы

* Новый независимый баланс магазина отклонён: он расходился бы с ручными Sale.
* Повтор покупки с новым UUID после timeout отклонён: вероятна двойная закупка.
* Один select_for_update для резерва отклонён: недостаточно для SQLite.
* Автоматическая очистка текста ответа regex отклонена: может изменить код или
  оставить секретную сумму рядом с удалённым названием. Неизвестный формат блокируется.
* Второй Telegram polling отклонён: конкурировал бы за offset существующего бота.

## Последствия

Существующий ручной кредитный сценарий сохраняется. С 14.11.2026 автоматическая
корзина также допускает отрицательный баланс и учитывает незавершённые суммы
отдельно от фактического списания. Корзина общая для группы, подтверждение
остаётся идемпотентным и проверяет текущую ревизию. Требуется сохранять
ключ digital_sales вместе с резервной копией. Сбой или неизвестный статус
может удерживать резерв до сверки — это намеренное предпочтение сохранности
денег повторной покупке вслепую. Полная техническая карта:
[цифровой магазин](../digital_shop_v2.md).
