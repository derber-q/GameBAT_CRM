# Avito Check

## Где находится

CRM → «Ценообразование» → «Avito Check» (`/crm/pricing/avito-check/`) открывает общую таблицу CD и Tech с реальной `AvitoListingConnection` и положительной суммой `CDWarehouseStock.quantity` / `TechWarehouseStock.quantity` по всем складам. Один Avito-профиль без связи не подходит. Реализация, товар в пути и будущие закупки не входят в остаток. Архивные карточки с остатком помечены; их продажные цены доступны только для чтения. Отображаются глобальный физический остаток, текущая себестоимость `cost`, себестоимость из импортного прайса, опт, цена Avito и отдельные минимумы РФ/Ростова с датами и кнопками поиска.

Опт и цена Avito редактируются с кнопкой «Сохранить» в колонке «Цены» через существующий AJAX-обработчик, сервис, аудит и штатные сигналы. Рядом с оптом показана разница оптовой цены и текущей себестоимости; она обновляется при вводе. Права на каждую цену и рекомендательные предупреждения сохранены. Эта операция не меняет дату найденного минимума. Сортировка `sort=name|oldest|newest` общая для CD/Tech; дата относится только к РФ, строки без российской проверки идут последними в обоих направлениях. Поиск и сортировка применяются вместе кнопкой «Применить».

«Себестоимость из прайса, ₽» берётся из последнего `ProcurementPriceList(is_trip_addition=False)` по `-created_at, -id`. Для совпадающих `(kind, product_id)` это сохранённый `stock_unit_cost = base_price_rub + delivery_rub`, включая исправления выбранного поставщика/ручной AED этой версии. Наценка, цены предоплаты/постоплаты и сегодняшние курсы в эту сумму не входят. Если обычного прайса или позиции в нём нет, показывается `—`: старые версии не используются, товар остаётся в таблице. Значение справочное, складскую оценку и продажные цены не пересчитывает.

Колонка артикула убрана; название занимает оставшуюся ширину после компактных колонок цен, даты и ручного поиска. Стили ограничены `avito-list-table` в `static/css/avito-check-list.css`. Поиск использует общий `filter_products_by_text`: название, артикул, ID, код CUSA/PPSA для CD и все штрихкоды `BarcodeRegistry`, включая дополнительные и коды с ведущими нулями. Дубли строк из-за нескольких штрихкодов не появляются. На узких экранах таблица прокручивается внутри своего контейнера.

Каждая `AvitoManualPrice` хранит профиль, `scope=russia|rostov`, положительный `Decimal`, серверное время и автора. Уникальна пара `(profile, scope)`. Повторное сохранение суммы обновляет только дату/автора этой географии. Миграция `integrations.0011_avito_manual_price_scopes` добавляет существующим строкам `russia`, сохраняя их ID, сумму, дату и автора; записи Ростова не создаются. Обе цены и даты независимы. Изменения записываются в историю товара с именем географии. При РФ > Ростов показывается предупреждение, сохранение разрешено; обе цены остаются введёнными сотрудником.

Для записи нужны оба права `pricing.view_pricing` и `pricing.change_retail_price`, штатная сессия и CSRF. Ручная запись не меняет учётные/продажные цены, остатки или очередь синхронизации. При отсутствии записи поле пустое, результат ReefAPI его не заменяет. AJAX-форма и расширение передают точный `expected_recorded_at` выбранного scope; устаревшая версия даёт HTTP 409 без записи и перехода. Часовой пояс отображаемой даты не используется как версия: передаётся исходный ISO с микросекундами.

Верхняя кнопка «Автоматическая проверка» открывает прежний пошаговый экран (`/crm/pricing/avito-check/automatic/`). Его очередь по-прежнему состоит из активных связанных товаров с положительным физическим остатком, упорядоченных по типу и ID. Здесь редактируются существующие `wholesale_price` и `avito_price`. Кнопка «Далее» сохраняет их через `pricing.services.update_product_prices`, аудит и сигнал синхронизации Avito. «Все товары» возвращает к таблице. Открытие любого из экранов само по себе не запускает платный поиск.

Ключ ReefAPI вводится в CRM → «Интеграции» → «API ключи» → «ReefAPI». Он хранится в `ReefApiCredential` в зашифрованном виде через существующий `integrations.crypto`; ключ шифрования находится вне Git. Пустой пароль в HTML, HTTP-запросы выполняются сервером. Файл ключа, переданный пользователем, импортирован в рабочее хранилище без помещения значения в Git или журналы.

«Ручной поиск» открывает Avito в новой вкладке без обращения к ReefAPI и работает без API-ключа. Для CD выставлены фильтры «Физический», «Новое», «Картридж» для NS/NS2 или «Диск» для PS/Xbox. Тип носителя задан именно фильтром, поисковый текст содержит нормализованное название и платформу. Платформа в форме Avito — «Любая», локализация не ограничена, как на скриншоте пользователя. География — вся Россия (`/all/`). Для Tech открывается обычный поиск по названию со словом «новый», без категории игр. Фильтры сверены с HTML формы Avito 04.10.2026: состояние `110390=431231`, формат `191956=3358159`, тип `167162=3270848` (диск) / `3270849` (картридж). Фильтры закодированы во внешнем URL и могут измениться на стороне площадки; пользовательский `context` в ссылку не переносится.

## Панель ручной проверки в Opera

Локальное расширение [ReSOURCE · Avito Check 1.7.0](../browser_extensions/avito_check/README.md) добавляет панель с типом товара, географией и минимумом только этой географии. «Поиск · РФ» / «Поиск · Ростов» запускают очередь с нажатого этапа текущего списка: товар 1 РФ → товар 1 Ростов → товар 2 РФ → товар 2 Ростов. Ростов без собственной цены остаётся пустым. Исходная вкладка CRM остаётся открытой для сессии и CSRF. После записи обновляются только выбранные поле, дата и версия; предупреждение пары обновляется отдельно. При ошибке/конфликте перехода нет. «Пропустить» переходит без записи. Без расширения ссылки открывают обычный поиск.

`GET /crm/pricing/avito-check/manual-context/` возвращает очередь, а `?product_id=<id>&kind=cd|tech&scope=russia|rostov` — одну цену. Общая выборка — `pricing/avito_check_catalog.py`. Все сообщения, поиски, сохранения и поиск поля DOM используют составной ключ `(kind, product_id, scope)`; числовые ID CD и Tech могут совпадать. Сохранение через `found-price/` требует kind/scope; для расширения дополнительно `manual_queue=1`, `expected_recorded_at` и повторная проверка положительного физического остатка. Прежнее расширение без scope получает понятную ошибку обновления. Очереди изолированы по ID вкладки в `chrome.storage.session`, повторные команды последовательны; CSRF не уходит на Avito.

РФ открывается через `/all`, Ростов — через `/rostov-na-donu` с тем же запросом и фильтрами носителя CD. Для Tech игровых фильтров нет. **Ограничение проверки 03.11.2026:** Avito вернул HTTP 429 «Доступ ограничен: проблема с IP»; переход и строгость городской выдачи/радиуса на живом сервисе не подтверждены. Тестовый браузер проверяет правильность сформированного пути, но не доказывает поведение Avito. Пользователь должен проверить город и радиус; дополнительные неподтверждённые параметры не придуманы.

Обновление: CRM → «Интеграции → Приложения и расширения», скачать Opera 1.7.0, распаковать в постоянную папку, перезагрузить/подключить через `opera://extensions`, обновить CRM и начать очередь заново. Проверки: `pricing.test_avito_scopes`, `pricing.test_avito_manual_queue`, `pricing.avito_scopes_browser_checks`, `pricing.avito_extension_browser_checks`, `integrations.test_manual_price_migration` и `browser_extensions/avito_check/test_background.cjs`.

С версии расширения 1.1.0 файл `cards.js` включает выбор цены из карточки выдачи. Обычная цена без скидки показывается без синего зачёркивания, скидочная зачёркивается. Нажатие на любую часть карточки выбирает обычную цену в поле панели; открытие объявлений блокируется. Выбор не отправляет запись в CRM. Для неясной обычной цены сохраняется ручной ввод без подмены её скидочной ценой. Обработка действует только в рабочей вкладке ручной проверки и распространяется на подгружаемые карточки. После обновления исходных файлов нужно перезагрузить расширение в `opera://extensions`, обновить вкладку CRM и начать новый ручной поиск.

Версия 1.2.0 устраняет зависимость оформления от разбора цены и добавляет разбор бонусной строки с несколькими суммами, например `1 890 ₽ −3 ₽ бонусами`, невидимых символов и вариантов без стандартного маркера старой цены. Обычная сумма отображается отдельным нормализованным текстом, чёрным и крупнее скидочной. Стили подключаются как CSS расширения через manifest (`cards.css`); номер версии виден в шапке панели. Проверка на примере Kena выбирает 1890, сохраняя 1887 только как зачёркнутую скидочную цену. Это локальный выбор; штатное сохранение в CRM выполняется отдельно.

## Экономный поиск трёх предложений

`integrations.reef_api.ReefApiClient` обращается к [документированным endpoint ReefAPI](https://reefapi.com/docs/avito): POST `/avito/v1/search` и POST `/avito/v1/listing`. Для игр запрос строится из названия карточки без проверенного префикса платформы, служебного CUSA/PPSA-кода и языковой пометки; платформа добавляется из отдельного поля товара. Проверенное название Avito-профиля может дополнять короткое имя без подмены платформы или издания. Сохраняется нормализация опечаток и подтверждение исправлений по игровой серии.

По умолчанию Search запрашивает всю Россию, `price_asc`, максимум две страницы, без fallback и с продвигаемыми объявлениями. Верхнего предела цены и автоматического повторного прохода нет. Собственные объявления и очевидно неподходящие строки исключаются до Listing; остальные дедуплицируются и сортируются по цене, при равенстве — по убыванию Avito ID. Проверяются до шести полных карточек, группами до трёх параллельно. Возвращаются до трёх подтверждённых предложений. Максимум одной экономной проверки — 2 × 2 + 6 = 10 кредитов. Нехватка трёх предложений не увеличивает бюджет.

«Искать глубже» запускается только отдельной кнопкой и ограничен 10 страницами и 20 карточками (до 40 кредитов). Дневной результат хранится в `AvitoPriceCheckResult`; повторная «Проверка» использует его без сетевых запросов. Изменение имени, платформы, значимой цены или версии правил требует обновления. «Обновить сейчас» принудительно выполняет экономную проверку с новыми сетевыми запросами. Полные карточки хранятся в `AvitoCheckListingCache` 24 часа, повторно проверяются текущими правилами и запрашиваются заново при изменении заголовка/цены в Search. Источником кеша служит SQLite, поэтому перезапуск сайта его не очищает. Старые результаты без версии новых правил скрываются до повторной проверки.

Полная карточка должна явно содержать параметр `Состояние: Новое`. Отклоняются Б/у, отсутствие уверенного состояния, цифровые товары, аккаунты, ключи, в том числе `Game-Key` вместо обычного картриджа, подписки, услуги, аренда и аналогичные схемы. Совпадение учитывает название, тип товара, бренд/платформу, Disc/Digital, Slim/Pro, память и издание, когда эти признаки есть в карточке. Нормализуются регистр, двоеточия, дефисы, апострофы, визуально похожие латинские и кириллические буквы внутри слова, некоторые римские цифры и односимвольные опечатки в длинных словах. Склеенное и раздельное написание соседних слов сравниваются как варианты. Числа, поколения платформ и значимые обозначения изданий остаются обязательными. Нормализуются PS5/PlayStation 5, NS2/Nintendo Switch 2, Xbox Series X и TB/GB; обычный Switch отделяется от Switch 2, Xbox One — от Series X. Если в заголовке явно указано поколение Switch 2, общий параметр `Платформа: Nintendo Switch` его не отменяет. Цена должна быть опубликованной фиксированной стоимостью товара; условная цена, цена «от», диапазон и явно указанная другая стоимость в описании исключаются. Единого нижнего порога цены нет.

Для CD дополнительно обязательно явное подтверждение физического носителя в параметрах, названии или описании. Значение «Формат: Цифровой», цифровые/электронные версии, коды активации, аккаунты и отсутствие диска/картриджа исключаются. Невидимые символы и смешение похожих букв нормализуются перед проверкой. Краткие `params_summary` также проверяются до Listing. Состояние «Новое» само по себе не подтверждает физическую копию. Для NS2 Cronos причиной ошибки было пропущенное значение «Формат: Цифровой» при обычном названии игры; проверка этого случая входит в регрессионные тесты.

Успешный результат, время, режим и счётчики запросов сохраняются в `AvitoPriceCheckResult`. Ошибка ReefAPI не изменяет товар и не перезаписывает прошлый результат. «Проверка» не сохраняет цены, остатки и объявления.

Фото текущего товара загружается через защищённый маршрут номенклатуры, доступный пользователям с правом просмотра цен. Для каждого предложения сохраняется город из `location.name` полной карточки ReefAPI; при отсутствии этого поля используется местоположение из Search, а в таблице выводится «—». Ранее сохранённые результаты получили города отдельным запросом к их объявлениям без изменения времени проверки и цен.

## Исторический замер прежнего TOP-5 (04.10.2026)

На повторяемой выдаче из 24 объявлений с пятью подходящими предложениями под пределом цены Search выполнил 2 запроса вместо 6 для полной выдачи; TOP-5 совпал. В сценарии с шестью объявлениями об аксессуарах предварительный фильтр исключил все шесть до платного Listing. В контролируемом замере шести Listing-запросов с одинаковой задержкой 80 мс последовательное выполнение заняло 0,482 с, три параллельных потока — 0,162 с; число запросов осталось тем же. Это замер искусственной задержки, не гарантия такого ускорения у ReefAPI.

На рабочем товаре `NS2 Animal Crossing` сохранённая пятая цена составляла 4 450 ₽. Проверка с пределом ровно 4 450 ₽ потребовала второй проход: 16 Search-запросов и 16 Listing-запросов. После добавления запаса 5% тот же TOP-5 (пятая цена 4 522 ₽) получен за 7 Search-запросов и 16 Listing-запросов, без изменения сохранённого результата. Полный поиск этого товара потребовал 9 Search-запросов; при тарифе 2 кредита за Search и 1 за Listing получаются 30 против 34 кредитов при одинаковом числе Listing. При сильном росте цен второй проход по-прежнему может увеличить расход, поскольку полнота TOP-5 важнее ограничения запросов.

## Границы результата

ReefAPI возвращает результаты в порядке Avito, который может быть нестрогим по цене. Экономная проверка рассматривает до 100 поисковых строк и 6 полных карточек, расширенная — до 500 строк и 20 карточек. Это дешёвые подтверждённые предложения среди просмотренных, а не гарантированный минимум по всей стране. Неоднозначный или отсутствующий носитель исключается; физическое объявление без достаточного описания может не попасть в результат. Кеш показывает состояние на указанное время проверки; для свежих данных предусмотрено принудительное обновление.
