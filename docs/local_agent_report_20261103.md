## Состав реализации

- `local_agent/`: Tk/ttk GUI, tray, DPAPI/ACL, профили, два независимых потока,
  потоковое скачивание, локальный SQLite-журнал, проверка/закрепление/очистка.
- `print_agent/profiles.py` и CLI/GUI: общая блокировка принтера; прежний
  Engine/Journal/WindowsDriver и протокол 1 сохранены. Старые журналы не удаляются.
- `crm_backups/`: серверная очередь, расписание, устройства/подключения,
  зашифрованные полные снимки, Range API, аудит и административные страницы.
- Явный default принтера, сохранение цели прежнего задания и ручного повтора.
- Каталог приложений с отдельным permission, явной публикацией и неизменяемыми ZIP.
- Сборщики Windows/Opera и offline-проверка восстановленной CRM.

Четыре миграции `crm_backups.0001`–`0004`: BackupConfiguration, BackupJob,
BackupEvent, BackupDevice, BackupEnrollment, PrintRouting, ApplicationArtifact.
Схемы товаров, продаж, кассы и остатков не меняются. container_runtime запускает
отдельный backup worker рядом с прежним supervisor, не второй supervisor.
Блокировка исполнителя привязана к SQLite, а не каталогу временных архивов.

## Сохранение гарантий

Print token, backup token и recovery key разделены. Сервер хранит хеши токенов
и только публичный ключ владельца. Устройство одно: уникальный активный слот,
сериализация операции, одноразовый код 10 минут, явная замена/отзыв с аудитом.
Печатающих профилей несколько, но один принтер не обслуживается двумя профилями
одновременно. Чужое задание/PDF не выдаётся. `uncertain` не перепечатывается.
Готовность Яндекса остаётся после подтверждённой печати, не после Spooler.

SQLite Backup API работает под коротким BEGIN IMMEDIATE; тяжёлые файлы предварительно
копируются/хешируются при доступной записи. В окне сверяются стабильные версии
источников, после него — полный manifest и инварианты. Проверяются WAL,
integrity/FK, FileField-ссылки, стабильность файлов/ключей и соответствие Fernet.
Полный пакет содержит protected_media, опубликованные программы, необходимые
секреты и manifest с SHA-256/размерами/миграциями/версией/dirty. Неверный состав
не объявляется успешным. Шифрование — X25519/HKDF-SHA256/AES-256-GCM, блоки 1 MiB,
полный тег до выдачи plaintext. Старые backups/Git/venv не включаются рекурсивно.

Расписание 03:00 Europe/Moscow настраивается на сервере. Пропуски не подменяются
успехом вчерашнего состояния; догоняющий снимок имеет фактическое время. Ограничены
диск, число ожидающих архивов и один активный снимок. Доставка — UUID/Range/ETag,
partial → размер/SHA → rename → журнал → подтверждение CRM. Последний исправный,
закреплённые, чужие файлы и активные загрузки защищены от очистки.
