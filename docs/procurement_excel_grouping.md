Доработка от 18.10.2026. Контрольная точка перед изменениями: `025747f5de588d265ed3c0f62f07656282ee451c`, ветка `main`, отправлена в `origin/main`. Перед ней прошли 950 Django-тестов, все 12 `test_*.cjs`, `check` и проверка миграций.

## Эталон и общий механизм

Эталон — фактическая страница «Номенклатура». Её порядок:

1. **Tech → Brand → ProductType → товар.** Используется существующий `tech_brand_groups` и обычный `tech_price_order`, без режима `for_excel`. Сохраняются действующие ранги Sony, Nintendo, портативной и прочей техники, порядок типов и товаров.
2. **CD → Platform → GameSeries → товар.** Платформы и товары следуют `cd_order_key`; серии сортируются по названию без учёта регистра, группа «Без серии» последняя внутри платформы. При равном названии товары упорядочены по ID.

После уточнения пользователя закупочные Excel используют **CD → Platform → товар**, без разделения по игровым сериям. Внутри платформы все товары сортируются по названию и ID через `cd_order_key`. Группировка Tech и структура самой страницы «Номенклатура» сохранены.

`catalog/nomenclature_grouping.py` содержит `get_nomenclature_grouping`, который используется самой страницей и сохраняет одновременно исходные строки платформы и её подгруппы серий. Адаптер `nomenclature_product_groups` для Excel берёт все строки платформы. Заголовок группы показывает путь, например `CD · Платформа: PlayStation 5` или `Tech · Sony · Геймпад`.

Механизм принимает исходные записи и функцию `product_of`, поэтому сохраняет дополнительные поля строки: количества, цены, снимки и распределения. Две строки одного товара с разными ценами или распределениями не объединяются. Для отсутствующих справочников в Excel предусмотрены подписи «Без платформы», «Без бренда», «Без типа»; отсутствие игровой серии не влияет на экспорт.

До и после выделения сервиса сравнен полный порядок рабочей номенклатуры: 3 442 CD, 476 Tech, 31 бренд и 8 платформ. Порядок и состав совпали.

| Документ | Генератор | Сохранённые данные |

| Закупочный прайс на склад | `price/excel.py: generate_procurement_stock_xlsx` | Остаток, текущая себестоимость, исходная закупочная база и доставка, сохранённая себестоимость с доставкой, количество, формулы сумм |
| Текущий состав клиентского или складского заказа | `orders/order_excel.py: order_xlsx` | Актуальные количества, сохранённые цены покупателя RUB; две строки для разных способов оплаты, нулевые позиции, итог |
| Заказ отдельному поставщику из рейса | `orders/trip_excel.py: supplier_order_xlsx` | Получатель, все исходные строки включая нули, цены AED и количества, скрытый артикул; имя файла с номером рейса и буквой поставщика |
| Новый состав конкретного заказа по поставщикам | `orders/order_supplier_excel.py: order_suppliers_xlsx` | Фактические количества распределения, исторические закупочные цены AED, названия и артикулы заказа, итоги и скрытые идентификаторы |

Во всех перечисленных генераторах используется один адаптер группировки. Состав выборки каждого документа задаётся прежними правилами его генератора: например, шаблон поставщика исключает архив и скрытые позиции, а исторический состав заказа сохраняет свои строки, включая архивированные впоследствии товары.

## Новый экспорт заказа

На странице клиентского и складского заказа есть кнопка **«Скачать состав по поставщикам»**. Маршрут: `GET /crm/orders/<id>/export/suppliers/`, имя `orders:export_suppliers`, файл `zakaz_<id>_suppliers.xlsx`.

Файл содержит один лист «По поставщикам». Верхний уровень — поставщик, внутри — Tech по бренду и типу, CD только по платформе. Видимые колонки: наименование, артикул, количество, цена AED, сумма AED. Сохраняются итоги каждого поставщика и общий итог. Денежные суммы рассчитываются `Decimal` один раз по товарным строкам; промежуточные итоги не включаются повторно в общий.

Источники данных определяет `build_order_supplier_rows`:

- Заказ без рейса: `CustomerProcurementOrderItem.selected_supplier` и `supplier_price_aed_snapshot`.
- Заказ в рейсе: только распределения его позиций в текущем рейсе. Получатель и цена — `allocation.line.supplier` и `allocation.line.supplier_price_aed_snapshot`; количество — `allocation.quantity`, а не общее количество `line.quantity` нескольких заказчиков.
- Нулевые распределения сохраняются. При правиле M → F положительное количество относится к F по сохранённой цене M; исходная нулевая строка также может присутствовать в внутреннем составе. Отдельный файл поставщика F не содержит обозначения источника цены M.
- Нераспределённый остаток количества попадает в «Поставщик не назначен» с пустой ценой. При отсутствии цены денежный итог явно не рассчитывается, а не заменяется нулём. Если распределение превышает количество заказа, выгрузка отклоняется с сообщением.

Скрытые колонки F:J содержат тип CD/Tech, ID товара, ID позиции заказа, ID распределения и ID фактического поставщика. Поэтому совпадающие ID CD и Tech и несколько распределений одного товара различимы. Снимки названий и артикулов берутся из заказа; текущие карточки используются только для группировки.

Для нового endpoint одновременно нужны `orders.view_order_detail` и `price.view_supplier_prices`. Полное название поставщика доступно только с `partners.view_supplier_details`; остальные получают букву. Endpoint допускает только GET, запрещает кеширование и не записывает бизнес-данные.

## Обратный импорт и совместимость

Идентификация основана на типе и ID, а не на названии группы или позиции в отсортированном списке. Генератор создаёт `_resource_meta` по фактическому номеру каждой товарной строки после вставки заголовков. Группировочные строки не включаются в метаданные. Скрытые поля, названия листов, тип документа, версия структуры и токен закупочного прайса сохранены.

| Импортёр | Изменения и проверенная совместимость |
| --- | --- |
| `import_supplier_price` / `import_supplier_price_files` | Алгоритм не менялся: идентичность строки проверяется по типу, ID и артикулу. Пустая цена удаляет предложение только включённого активного товара. Поддержаны прежние титульные шаблоны с заголовком в строке 8 и пятью колонками, современные шесть колонок с заголовком в строке 1 и новые группы |
| `import_procurement_order_xlsx` / `import_procurement_order_files` | Добавлены проверки границ и уникальности номеров строк, названия и артикула по снимку версии. Перестановка видимых строк без обновления технической разметки отклоняется. Прежний общий файл без групп и отдельные CD/Tech поддерживаются. Цены из заполненного файла по-прежнему не заменяют сохранённые цены версии |
| `import_stock_procurement_order_xlsx` | Алгоритм не менялся. Поддерживаются прежний формат из семи колонок и действующий из девяти; количество и артикул читаются из соответствующих колонок по технической разметке |

Формула складской строки остаётся `=G<строка>*H<строка>`; её адрес формируется при записи строки. Итоги используют корректные границы. Клиентский прайс сохраняет семь итоговых формул, колонки B/D с ценами и C/E с количествами. Группы заблокированы для ввода, проверки количества применяются к товарным ячейкам.

Составы заказов и таблицы рейсов — отчёты; их не используют как заполняемые закупочные шаблоны. Поддержка ранее выдававшихся закупочных форматов сохранена. Несовместимых форматов среди проверенных не обнаружено. Переставленные видимые строки с прежней технической разметкой считаются повреждённым файлом и отклоняются. Миграции не требуются.
