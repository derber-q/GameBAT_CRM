# Мобильная витрина ReSOURCE

Дата: 3 октября 2026. Продолжение [правок по референсам](resource_refinement.md).

## Что исправлено

- На телефоне поиск и корзина доступны из компактной шапки. Меню и фильтры открываются диалогами с блокировкой фоновой прокрутки и возвратом фокуса. Поля имеют размер шрифта 16 px; основные кнопки — минимум 44 px. Учтены safe area и изменение доступной высоты окна.
- Каталог получил горизонтальные карточки на телефоне. Фотографии используют закрытые responsive-версии WebP 320/640/960 px с сохранением пропорций. Для главного баннера подготовлен мобильный файл. Размеры изображений зарезервированы; ниже первого экрана применяется lazy loading.
- Выбор категории больше не отправляет фильтры немедленно. Применение явное; закрытие отменяет изменения. Неприменимые параметры CD/Tech очищаются. Выбор отражается в URL, счётчике и подписях; пагинация сохраняет параметры. Возврат из товара сохраняет запрос каталога и прокрутку.
- Добавление и редактирование корзины выполняются без перехода страницы. Повторный запрос добавления с тем же идентификатором операции не увеличивает количество второй раз. Во время запроса форма блокируется; результат сообщается без перехвата нажатий уведомлением.
- Для большой корзины добавлена компактная панель суммы и перехода к оформлению. Она скрывается при видимом блоке оформления и при уменьшении окна клавиатурой. После изменения количества сохраняется прокрутка.
- Исправлена ошибка согласования корзины: изменение количества больше не принимает незаметно новую цену или остаток. Изменённые строки отмечаются, оформление требует явного подтверждения актуального состава.
- Контактные данные подставляются автоматически. Дополнительный телефон и комментарий необязательны; ошибки выводятся рядом с полями. Черновик переживает обновление страницы и замену содержимого корзины, разделён по контактам.
- При потере ответа оформления повторная отправка блокируется до проверки статуса исходной операции. Уже созданная продажа открывается без дублирования; серверная идемпотентность сохранена. Корзина и её снимок очищаются после успеха.
- Визуальная проверка выявила и устранила дубли мобильных кнопок на desktop, нечитаемые нативные селекты WebKit и узкую заглушку фото в карточке товара.

## Воспроизведение исправления фильтров

1. На ширине 390 px открыть каталог, затем фильтры.
2. Выбрать CD и минимальную цену 1001. Выдача и URL до нажатия «Применить» остаются прежними.
3. Закрыть панель и снова открыть: несохранённые значения сброшены.
4. Повторить выбор и применить: в URL появляются параметры, выдача и подписи соответствуют им.
5. Открыть товар и вернуться к результатам: параметры сохраняются.

Сценарий закреплён в `resource_storefront/browser_checks.py`; отмена, переключение категории, фокус и отсутствующие поля дополнительно проверяются в `test_storefront_js.cjs`. Серверные комбинации фильтров проверяет `test_refinement.py`.

## Проверки

Браузерные проверки выполняются в Chromium и WebKit через Playwright с эмуляцией viewport и touch. Это **не проверка на физических iPhone или Android**.

- Полный путь: персональная ссылка → главная → каталог → фильтры → товар → корзина → оформление → подтверждение.
- Ширины 360, 375, 390, 412, 430, 768 и 1440 CSS px; отдельно горизонтальное окно 844 × 390. Проверяется отсутствие горизонтального выхода документа и размеры кнопок товара.
- Корзины 1, 10 и 30 позиций. Наполнение большой корзины ускорено запросами из браузерной сессии; добавление из карточки, изменение количества и оформление выполняются через интерфейс.
- Отмена фильтров, пустая выдача, неверный диапазон цен, длинные названия, отсутствие фото, возврат из товара, восстановление черновика и прокрутки.
- В Chromium: задержка 150 мс, загрузка 100 КБ/с, отдача 50 КБ/с; проверка загрузки шрифта и повторного добавления после offline.
- В обоих движках: сервер принимает заказ, ответ намеренно обрывается; проверка статуса возвращает исходный заказ. Проверяется по одной продаже на сценарий и отсутствие кассовых поступлений.
- Серверные тесты покрывают изменившиеся цены/остатки, повторное оформление, отзыв доступа, разделение контактов и закрытые миниатюры.

Тестовые продажи создаются только в отдельной тестовой SQLite. Для реалистичного наполнения браузерная проверка читает из рабочей базы только названия товаров и пути фотографий. Рабочие остатки и продажи не изменяются. Новых миграций для мобильной доработки нет.

## Ограничения

Физические телефоны, нативная экранная клавиатура, браузеры внутри мессенджеров и особенности конкретных версий Safari не проверены. Для панели фильтров проверено уменьшение доступной высоты до 430 px; это не воспроизводит все особенности настоящей клавиатуры. Смена цены/остатка проверена серверными тестами, без конкурентной покупки через второй физический телефон. Полный suite всей CRM в рамках этой доработки не запускался. Production-развёртывание не выполнялось.
