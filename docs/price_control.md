# Контроль продажных цен

Актуализация 23.09.2026: текущий default наценок — 189 ₽ (миграция `0018_price_markups_189`), сохранение цены выполняется AJAX через `pricing-scroll.js`. У геймпадов Sony разово изменены данные на 289/489 ₽; это не default модели. Приведённые ниже 200 ₽ и результаты 430 тестов описывают первоначальную реализацию. Текущие правила и результаты — в `architecture.md` и `verification.md`.

## Интерфейс

Старая проверка `Avito − себестоимость < 200 ₽` удалена из pricing/views.py, pricing.js, шаблона таблицы и CSS. Классы avito-low-margin / avito-price-readonly-warning больше не используются. Старый тест заменён тестом нового правила.

По уточнению пользователя **на странице «Ценообразование» нет полей редактирования наценки**. Они находятся в карточке CD/Tech, в блоке «Коммерческая информация»: Avito и его наценка рядом, Яндекс Маркет и его наценка рядом, оптовая цена отдельно.

Таблица цен показывает только цены и предупреждения. Сохранённые пороги передаются скрипту как скрытые данные, а не как поля формы. Цены с нарушением выделяются красной рамкой и светло-красным фоном. Подсказка содержит одну или обе причины.

## Модель и миграции

На ProductBase добавлены два независимых поля для CD и Tech:

- `avito_markup_from_wholesale` — наценка от опта для Avito;
- `yandex_markup_from_wholesale` — наценка от опта для Яндекс Маркет.

Оба — DecimalField(max_digits=20, decimal_places=2), default Decimal('200.00'), null=True, blank=True. Отрицательные значения запрещены валидатором и ограничением БД. У оптовой цены отдельного порога нет. Других независимых продажных цен в модели не найдено; цены поставщиков не являются продажными.

Миграция 0016_price_markup_fields добавляет поля и ограничения. Миграция 0017_initialize_price_markups устанавливает 200 ₽ существующим CD/Tech. Новые карточки получают default модели. Форма создания, как и раньше, не содержит продажных цен; после создания пороги можно изменить или очистить в карточке.

Применение проверено на 1 919 CD и 326 Tech. Резервная копия перед миграцией: backups/before_price_markups_20260922_185716/db.sqlite3. Сравнение всех прежних столбцов всех таблиц (кроме журнала миграций) подтвердило отсутствие изменений цен, себестоимости, остатков, операций, истории и связей.

## Правила

Единый backend-сервис: pricing/warnings.py. Используется текущая глобальная себестоимость `product.cost`, та же, что отображается в проекте. Дополнительных запросов на строки нет.

Для Avito/Яндекс Маркета:

`warning = (price, wholesale, markup заполнены и price - wholesale < markup) OR (price, cost заполнены и price < cost)`.

Для оптовой цены: только `wholesale < cost` при заполненных значениях.

- Цена равна оптовой: предупреждение при пороге > 0.
- Цена ниже оптовой: предупреждение при любом заполненном неотрицательном пороге.
- Разница равна порогу: предупреждения по наценке нет.
- Порог 0: нормальное значение, не равнозначное пустому.
- Пустой порог: отключает только проверку наценки конкретного канала.
- Пустая цена: предупреждения нет.
- Пустой опт: проверка наценки пропускается, проверка себестоимости остаётся.
- Пустая себестоимость: проверка себестоимости пропускается. Текущая модель обычно хранит cost как обязательное значение, но сервис умеет обрабатывать None.

## Динамическая подсветка

pricing.js пересчитывает все цены строки/карточки на input и change. Изменение опта пересчитывает оба канала; изменение порога в карточке пересчитывает соответствующую цену. Read-only цены тоже поддержаны. JavaScript использует BigInt в копейках, не float; backend — Decimal. Серверный рендер таблицы и карточки применяет те же правила, поэтому подсветка работает без JS и сохраняется после reload.

Предупреждения не входят в валидацию сохранения. Нет setCustomValidity, блокировки submit или автоматической корректировки цен. Обычная проверка типа/формата/неотрицательности остаётся прежней. Сохранение ниже опта и себестоимости проверено тестами.

## Права, история и Admin

Avito markup использует существующее право pricing.change_retail_price; Yandex markup — pricing.change_yandex_market_price. PRICING_FIELDS включает цены и настройки для редактирования/аудита, PRICE_FIELDS по-прежнему включает только три реальные цены.

Новые поля включены в карточки, optimistic-lock token, ProductChangeEvent/ProductFieldChange и Django Admin. В Admin они доступны как обычные model fields и read-only при отсутствии права, включая создание через Admin. В карточке защищённые поля нельзя изменить поддельным POST. Изменения порога записываются с названием поля, прежним и новым значением.

Логика продаж, статистики, себестоимости, движения запасов и интеграции Avito не менялась. Пороги не входят в цену, передаваемую Avito, и не влияют на разрешение синхронизации.
