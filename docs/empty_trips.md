# Пустой рейс и выбор прайса первым заказом

На странице «Заказы и рейсы» доступна кнопка **«Создать пустой рейс»**. Название необязательно. Созданный рейс сразу появляется в списке, имеет статус «В работе» и открывается в обычной карточке рейса.

## Добавление товаров и заказов

1. **«Добавить дополнительные товары»** доступно сразу, до первого обычного заказа. Пока прайс рейса не определён, на первом шаге выбираются курсы и доставка из сохранённого закупочного прайса. По умолчанию предложен последний обычный прайс; выбор виден и доступен для изменения.
2. Этот выбор относится только к расчёту дополнительной партии. Существующий механизм создаёт отдельный служебный прайс и новые заказы на склад/для партнёров. Основной прайс рейса остаётся неопределённым.
3. **«Добавить заказы»** показывает свободные созданные заказы с получателем и номером прайса. Первый обычный заказ закрепляет свою версию прайса за рейсом. Несколько выбранных заказов должны относиться к одной версии; при ошибке вся операция откатывается.
4. После привязки доступны обычные заказы только из этой версии прайса. Прежние дополнительные партии сохраняют собственные снимки цен, доставки, количества и клиентских сумм. Их цены не пересчитываются по выбранному основному прайсу.

Обычная кнопка «Добавить в рейс» на странице отдельного заказа также предлагает незакреплённые рейсы и выполняет ту же привязку. Для изменения состава сохраняются прежние проверки статуса, передачи в документы, прибытия и версии изменений. Рейс только с дополнительными товарами поддерживает Excel, инвойсы, редактирование строк и фактическое прибытие; после прибытия добавление товаров/заказов блокируется.

## Код и совместимость

Миграция и исправление старых записей не нужны. `price_list` у `SupplierOrderBatch` уже допускает NULL. Современный рейс отличает основной прайс **или** уникальный `creation_key`; старые подборки без обоих признаков остаются подборками. Для выборки рейсов используются `SupplierOrderBatch.objects.trips()` и свойство `is_trip`, а не только проверка наличия прайса.

Создание использует прежнюю транзакцию и уникальный ключ запроса; повтор создания возвращает тот же рейс, в том числе после добавления в него заказов. Изменения записываются в `SupplierTripChange`. Первая привязка прайса хранится в `bound_price_list_id` события добавления заказа. Выбор курсов дополнительной партии сохраняется в черновике, отпечатке расчёта и аудите; изменение состава/тарифов/прайса между проверкой и сохранением требует повторной проверки. Сами заказы и их цены создаются существующими сервисами.

Права создания/изменения рейса прежние: `orders.generate_supplier_orders`, `orders.edit_created_order`, `partners.view_supplier_details`, `price.view_supplier_prices`. Для дополнительных товаров дополнительно требуется `orders.create_order`.

Основные файлы: `orders/models.py`, `trips.py`, `trip_views.py`, `forms.py`, `trip_additions.py`, `trip_addition_views.py`, шаблоны `trip_empty_create.html`, `trip_add_orders.html`, `trip_detail.html`, `trip_addition.html`.

## Проверка

`manage.py test orders --noinput` проверяет сценарий вместе со всеми тестами заказов. Новые проверки: `orders.test_empty_trips`. В Chromium полный путь создания, дополнительной партии и первого обычного заказа проходит в `orders.empty_trips_browser_checks` с отдельной SQLite (`--settings=sales.system_browser_settings --noinput`). Рабочие заказы и внешние API в тестах не используются.
