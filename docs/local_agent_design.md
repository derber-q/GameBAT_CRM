# ReSOURCE Local Agent: контракт и последовательность проверок

Задание от 03.11.2026. Исходные main / e309bb37011635fc40883d15686b3ccbf5f0d3d7.
Незакоммиченные Telegram-шаблоны и общий звук сохраняются. Рабочие данные,
системные службы, автозапуск и принтер при разработке не переключаются.

## Этапы и допуск

A. Контракты, инвентаризация, негативные тесты. B. Снимок, шифрование,
восстановление искусственной БД. C. Отдельное устройство и API.
D. Windows GUI, журнал скачивания/хранения. E. Профили и назначение печати.
F. Административные страницы. G. Проверенные сборки и каталог скачивания.
H. Регрессия и инструкции. Следующий этап допускается после отдельной проверки
предыдущего. Результаты записываются в отчёт; наличие исходников не равно внедрению.

## Границы доверия

Печать сохраняет print_agent.Engine/Journal/WindowsDriver, протокол 1 и прежний
порядок PDF → подтверждение драйвера → READY_TO_SHIP. Неизвестный результат
требует решения сотрудника. Профиль получает собственный каталог и блокировку;
старый журнал не переносится и не удаляется автоматически.

Backup API не принимает cookie, Origin, произвольный путь и команды shell.
Токен устройства (случайные 256+ бит, на сервере SHA-256) независим от print-токена.
Один активный получатель защищён ограничением БД; смена — отдельный POST
суперпользователя, отзыв и аудит. HTTP разрешён только для local_live loopback,
иначе HTTPS. Перенаправления клиента запрещены.

## Формат архива и восстановительный секрет

Архив версии 1: ограниченный JSON-заголовок, одноразовый X25519, HKDF-SHA256,
AES-256-GCM с 96-битным случайным nonce и полным 128-битным тегом.
Заголовок аутентифицирован как AAD; данные читаются блоками до 1 MiB.
До успешной проверки GCM никакое содержимое не извлекается и не используется.
Сервер получает только публичный ключ владельца. Приватный ключ хранится
отдельно у владельца в зашифрованном PKCS8; токен устройства не расшифровывает архив.
Идентификатор ключа — SHA-256 публичного ключа. Ротация не удаляет прежние ключи.
Это собственный формат контейнера над стандартными криптографическими примитивами,
не новый алгоритм шифрования; его совместимость и проверка повреждений тестируются.

Внутри — manifest.json, database.sqlite3 (или database.dump), protected_media,
recovery/secrets.json с необходимыми действующими секретами и метаданные версии,
окружения/миграций. Никаких исходников, старых backups, Git, журналов и venv.
Наличие незакоммиченных изменений отмечается честно: HEAD не описывает весь код.
Секреты и внутренний манифест не публикуются в API; наружу только безопасная сводка.

## Согласованность снимка

SQLite: отдельное соединение с BEGIN IMMEDIATE кратковременно удерживает всех
писателей БД; другое read-only соединение выполняет Online Backup API. Архивируется
только самостоятельный проверенный снимок, никогда активный db.sqlite3/WAL/SHM.
Тяжёлые файлы предварительно копируются в приватный staging без блокировки БД;
копия проверяется по SHA-256. Версии источников фиксируются по device/inode,
размеру, mtime_ns и ctime_ns до/после подготовки. В коротком окне сверяются
состав и версии перед/после снимка БД; любая смена прекращает копию.
После снятия блокировки отдельно проверяются все FileField-ссылки снимка,
состав/хеши staging и ключи. Никаких незавершённых архивов наружу не выдаётся.
Если файл отсутствует, изменён или окно превышено, операция завершается ошибкой,
архив не объявляется полным. Неизменяемые файлы архивируются по проверенным путям.
Согласованное окно ограничено по времени; шифрование и загрузка выполняются позже.
Длинная загрузка на Windows не блокирует торговлю.

PostgreSQL использует отдельный адаптер pg_dump и собственное согласованное окно;
непроверенный путь не включается автоматически. Доступность адаптера не означает
испытания PostgreSQL. Восстановление требует пустого изолированного каталога,
проверяет тег, manifest/размеры/хеши, безопасные пути, integrity/FK и данные.
На рабочую БД автоматического восстановления нет.

## Жизненный цикл и хранение

Настройка выключена по умолчанию. Серверная очередь и расписание 03:00
Europe/Moscow независимы от Windows. Одна тяжёлая операция, устойчивый UUID,
ограничение ожидания/диска. Перезапуск не выдаёт прерванный снимок за готовый.
Пропущенный день остаётся пропущенным; догоняющий снимок имеет фактическое время.
Успех доставки фиксируется только по подтверждению устройства после SHA-256/размера.

Windows: DPAPI защищает токены; загрузка в .partial, Range/ETag одного UUID,
проверка и атомарный rename, долговечный журнал. Очистка выключена по умолчанию;
разрешены только зарегистрированные проверенные файлы своего каталога,
без ссылок и с совпадающим хешем. Последний исправный, закреплённые и активные
файлы сохраняются. После неудачной загрузки очистка не выполняется.

Копия на том же физическом диске не защищает от отказа диска. Потеря единственного
приватного ключа делает архивы нечитаемыми. Оба ограничения видны в инструкциях.

[GCM и потоковый Cipher](https://cryptography.io/en/46.0.3/hazmat/primitives/symmetric-encryption/),
[SQLite Backup API](https://docs.python.org/3.14/library/sqlite3.html#sqlite3.Connection.backup).
