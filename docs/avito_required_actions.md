# Необходимые действия Avito

## Назначение

Блок расположен на странице «Интеграции → Avito», перед ручной синхронизацией цен и остатков.
Это список ручных действий, а не управление публикацией через API.

| Условие | Действие |
| --- | --- |
| Связанное опубликованное объявление, глобальный остаток 0 | Снять с публикации, красная ячейка |
| Связанное опубликованное объявление, sell_on_avito=False | Снять с публикации, красная ячейка |
| Связанное архивное объявление, остаток > 0, sell_on_avito=True | Опубликуйте объявление, зелёная ячейка |
| Остальные состояния | Нет строки |

Флаг продажи сохраняет прежнюю семантику: отключённому товару существующий outbound sync передаёт количество 0. Новый блок не предлагает публиковать такой товар.

## Остатки и производительность

Используется существующий `global_stock`, сумма `quantity` из WarehouseStock по всем складам, без реализации.
Для массового списка передаётся предварительно рассчитанная карта остатков. Один запрос получает связи, товары и remote listings через select_related, ещё два агрегируют CD и Tech. Число запросов не растёт с количеством товаров.
Нет связей — нет строки. Архивированные карточки CRM исключены. Устаревшие связи не восстанавливаются.

## Статусы и источники

Нормализация централизована в `integrations/required_actions.py`:

- `active` → опубликовано;
- `old` → истёкшее/неактивное объявление, для которого предлагается ручная публикация;
- `removed`, `blocked`, `rejected`, модерация, пустые и неизвестные значения → OTHER, без действия.

22.09.2026 выполнены реальные read-only запросы текущим клиентом:

- GET /core/v1/items: получено `active` и URL объявления;
- GET /core/v1/accounts/{account_id}/items/4442998825/: получено `old` и URL объявления.

Официальные источники, указанные пользователем:

- [Item API](https://developers.avito.ru/api-catalog/item/documentation)
- [Auth API](https://developers.avito.ru/api-catalog/auth/documentation)
- [Stock Management API](https://developers.avito.ru/api-catalog/stock-management/documentation)
- [Autoload API](https://developers.avito.ru/api-catalog/autoload/documentation)

**Ограничение проверки документации:** официальный портал возвращал HTTP 429, браузерный поиск также не смог прочитать страницы. Файл «Официальная-документация-Avito-API.txt» на рабочем столе содержит ссылки и общие требования, но не контракт статусов. Поэтому полная сверка с актуальной официальной схемой пока не подтверждена. Реальные значения `active` и `old` проверены на аккаунте и соответствуют уже используемой интеграцией обработке. Дополнительные значения вроде `archived` не включены по догадке. Требуется сверка официальной схемы после восстановления доступа.

## Ссылки и интерфейс

URL берётся из remote listing или его безопасного snapshot, не конструируется из названия. Разрешены HTTPS, хосты avito.ru/www.avito.ru, без userinfo и нестандартного порта. Если безопасного URL нет, показывается предупреждение вместо опасной ссылки.
Открытие в новой вкладке с `rel="noopener noreferrer"`.
Сначала идут снятия, затем публикации; внутри — сортировка по названию и ID. Окрашивается только ячейка действия. Есть счётчик, глобальный остаток, название и ID CRM, артикул и исходный статус Avito. Пустое состояние: «Необходимых действий нет.»

## Обновление

POST-кнопка создаёт/перезапускает дедуплицированную задачу `status_refresh` в существующей DB-backed очереди. Повторные нажатия не создают параллельные задачи.
Существующий worker использует существующий `refresh_remote_listings(check_linked_statuses=True)` и тот же AvitoClient. Отдельные прежние задачи часового обновления списка и синхронизации количества не заменены новым механизмом.
Сервис читает актуальный список, обновляет remote metadata и дополнительно запрашивает детали отсутствующих связанных объявлений. Пустой активный список допустим, если статусы связей подтверждены через детали.
Не импортируются данные в карточки товаров, склад, продажи, приходы или реализацию. Нет вызовов update_stock/update_price/publish/unpublish в новой задаче.
Синхронизация quantity/price — отдельный прежний процесс.

UI показывает ожидание/обновление, опрашивает защищённый endpoint без HTTP-кеша и после окончания перезагружает список с пересчётом остатков. Старые данные явно обозначены до завершения. Если worker остановлен или занят, UI сообщает об ожидании, а не об успехе.
При API/auth/network ошибке сохраняется причина, временные ошибки повторяются ограниченное число раз. Нет ложного «обновлено». Отсутствие объявления и HTTP 404 не считаются архивом: связь сохраняется, статус отмечается как неподтверждённый, ошибочное действие не показывается. Ранее полученные данные не удаляются молча.

## Права

Просмотр блока и статуса задачи: `integrations.view_avito_integration`.
POST-обновление: `integrations.manual_avito_sync`, CSRF-проверка. Новых прав нет.

## Изменённые файлы

- integrations/required_actions.py — сервис списка, enum, нормализация, URL, пакетный расчёт.
- integrations/services.py — пакетный вариант global_stock, проверка деталей отсутствующих связанных объявлений.
- integrations/models.py, integrations/migrations/0004_avito_status_refresh_job.py — новый тип существующей задачи.
- integrations/tasks.py — выполнение фонового read-only refresh, повторы и ошибки.
- integrations/views.py, integrations/urls.py — контекст страницы и защищённые endpoints.
- templates/integrations/avito_dashboard.html, templates/integrations/_required_actions.html — блок.
- static/css/avito-required-actions.css, static/js/avito-required-actions.js — оформление и ход обновления.
- integrations/test_required_actions.py — регрессионные проверки.

## Проверки

Новые тесты покрывают CD/Tech, все основные сочетания остатка/статуса/флага, отсутствие связи, архивную карточку, глобальный остаток нескольких складов, исключение реализации, неизвестные/заблокированные/удалённые статусы, безопасную ссылку, цвета, пустое состояние, права/POST, дедупликацию, фоновое выполнение без outbound sync, ошибки/повторы, свежие детали вместо cache, исчезновение исправленных строк и 3 запроса для 21 связи.

Полный набор: 423 теста, 6 падений (четыре подслучая catalog.test_product_browsing и по одному pricing.tests / sales.tests). Все падения — ожидание прежнего `app.js?v=global-barcode-1`, изменённого до этой задачи. Новая функциональность этот файл и ссылку не меняла. Эти посторонние тесты не исправлялись в рамках Avito.
Отдельный финальный прогон `manage.py test integrations --noinput`: **61 тест, OK**, включая 16 новых тестов блока.
`manage.py check` — ошибок нет. `makemigrations --check --dry-run` — незаписанных изменений моделей нет.

Перед миграцией создана резервная копия `backups/before_avito_actions_20260922_173616.sqlite3`. Существующие пользовательские изменения сохранены. Коммит и пуш не выполнялись.

Контрольный запуск задачи №579 завершился успешно. При сравнении 40 таблиц товаров, складов, реализации, продаж, приходов, кассы и связей Avito с резервной копией изменений не обнаружено. SQLite integrity_check: ok. Сетевой адрес сайта возвращает HTTP 200.
