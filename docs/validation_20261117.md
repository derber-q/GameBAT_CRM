# Проверка контрольной точки CRM — 17 ноября 2026

Проверена накопленная рабочая версия, включая пользовательское изменение
порядка позиций закупочного прайса: незаполненные и неположительные наценки
показываются первыми; внутри групп сохраняется каталоговый порядок.

## Условия проверки

Тесты выполнялись на отдельной копии исходников с искусственными данными,
отдельными SQLite, медиа и ключами. Рабочая база не использовалась как
тестовая фикстура. Исходящие соединения Python-тестов за пределы loopback
блокировались; внешние API и физическая печать подменялись.

Windows: Python 3.14.7; отдельная проверка Linux выполнялась в служебном
контейнере с `--init`, без сети и без подключения рабочих данных.
Настройка `--init` соответствует рабочему Compose.

В повторном полном Django-прогоне использован MD5-хешер только в локальных
тестовых настройках для ускорения фикстур пользователей. Рабочие настройки
хеширования не менялись. Тест восстановления пароля отдельно принудительно
использует PBKDF2, чтобы ускорение suite не скрывало несовместимость архива.

  Они затем выполнены в Linux: **3 системных теста, `OK`**, включая соседнюю
  проверку схемы запросов шлюза.
- После последней пользовательской правки и изменения CI отдельно выполнены
  новые тесты сортировки и выбора режима CI, а также затронутые проверки
  уведомлений и справочника: успешное завершение соответствующих процессов.
- Все **31 файл `test_*.cjs`** завершились с кодом 0.
- Отдельный сценарий `local_test`: миграции искусственной базы, запуск сайта,
  браузерная проверка, остановка принадлежащего проверке дерева процессов —
  код 0; рабочие данные не подключались.
- Полный перечень браузерных проверок: **50 модулей, 77 сценариев, все процессы
  завершились с кодом 0**. В том числе выполнены оба сценария настоящего
  MV3-расширения на подменённых страницах Avito, мобильная навигация
  Chromium/WebKit, приёмка и финализация рейсов, оплаты и витрина.
- Django `check`: ошибок нет. `makemigrations --check --dry-run`:
  новых миграций не требуется. Проверены ссылки проекта, технический
  справочник, синтаксис/неопределённые имена, зависимости `pip check`

Первый прогон выявлял ошибки и устаревшие фикстуры; его результат не считается
успешным. Общий браузерный процесс на Windows дважды завис внутри Playwright
на сценариях расширения. Отдельные модули запускаются в новых процессах с
разными тестовыми БД и ограничением времени. Зависшие процессы останавливались
по проверенной команде конкретного тестового запуска, без остановки CRM.

## Исправления, найденные проверками

1. Резервирование в Windows/Python 3.14: некоторые `DirEntry.stat()` возвращают
   неполные идентификаторы файла. Для Windows используется свежий `os.stat`
   без следования ссылкам. Проверки hardlink/symlink не отключены; реальный
   hardlink покрыт регрессией. Пробное восстановление искусственного архива
   проверяет бизнес-данные, медиа и расшифровку.
2. Автоматическое обновление цифровых тарифов не требует выдуманного пользователя
   для допустимого системного `edited_by=None`. Сохраняются валидация остальных
   полей и аудит ручного редактирования.
3. Значок запуска обработчиков заменён с символа шрифта на встроенный SVG.
   Состояние ошибки по-прежнему показывает `!`. Размер кнопки и права доступа
   сохранены; проверены состояния, доступная подпись и работа без звука.
4. Счётчик Avito не начинает новый запрос при скрытии/закрытии страницы,
   когда WebKit уже блокирует сеть. Фоновый опрос по таймеру сохранён;
   возврат во вкладку вызывает немедленное обновление. Добавлена JS-регрессия.
5. Мобильная финализация ограничивает ширину элементов панели действий
   и переносит длинные подписи. Браузерная проверка ждёт применения адаптивной
   раскладки после изменения viewport и сохраняет диагностику переполнения.
6. Браузерные фикстуры витрины больше не читают рабочую SQLite из Windows.
   Товары, остатки и обложки создаются искусственно.
7. Фикстуры продаж, реализации, предоплаты и рейсов приведены к действующим
   ограничениям и этапам приёмки. Проверки не разрешают в рабочем коде
   запрещённую продажу партии другой площадки или обход финализации.
8. Файловая тестовая SQLite использует IMMEDIATE и busy timeout для настоящих
   проверок конкурентной записи. Django 5.2 при Windows spawn неправильно
   открывает файловые копии: Windows CI запускает suite последовательно,
   Linux сохраняет четыре процесса. Workflow устанавливает оба используемых
   движка: Chromium и WebKit.
9. Генератор технического справочника исключает только служебный маршрут
   раздачи статики Django development server. Прикладные маршруты остаются
   в справочнике; независимость от DEBUG проверена регрессией.

## Проверка рабочей установки и ограничения

В Docker отдельно выполнены диагностические команды:

- `verify_inventory`: остатки склада и реализации согласованы;
- `verify_cash`: кассы и сейфы согласованы с журналом операций;
- `check_worker_health`: подтверждены рабочие циклы и доступность необходимых
  агентов печати;
- `migrate --check`: ожидающих миграций нет.

Эти команды не исправляли записи и не проводили продажи. Глобальная проверка
не создавала реальных покупок, отправлений, публикаций Avito или заданий печати.
Подмена внешних API не доказывает доступность поставщика в произвольный момент.
Проверка Git-индекса исключает базы, секреты и локальные архивы; тестовые логи,
изображения и БД остаются в игнорируемом `outputs/`.
