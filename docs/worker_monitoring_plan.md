# План мониторинга обработчиков

Исходное состояние 31.10.2026: `main`, `ed6490e49ab107da2598ec27d3772f0f278da880`.
В дереве есть многочисленные пользовательские изменения, включая документацию и
общую статику. Исходные версии затрагиваемых файлов сохранены локально в
`outputs/worker_monitoring/baseline/`. На этапе разработки коммит, push и миграция
рабочей БД не были разрешены. Последующее согласованное внедрение зафиксировано
в `worker_monitoring_report_20261031.md`; разрешения на коммит/push не было.

## Техническая карта до изменения

- `run_integration_worker` последовательно вызывает существующие процессоры Avito,
  Google и Яндекса; `all` и отсутствие `--service` покрывают три очереди.
- `AvitoSyncJob` при готовых заданиях предпочитает ручную сверку/статусы;
  `SyncJob` Яндекса — события/заказы, затем прочее, затем сверку.
- `GoogleSheetsSyncJob` сортируется по `run_after`, периодическое задание переиспользуется.
- `run_label_print_worker` вызывает `process_print_jobs`. Состояния `printing`,
  `spooled`, `uncertain` защищают физическую печать; мониторинг их не меняет.
- `start_localhost.ps1` сохраняет исправный сайт, запускает недостающие worker.
  `scripts/local_network.ps1` распознаёт общий worker. Владение запуском передаётся
  одному supervisor, распознавание Windows остаётся в общем PowerShell-модуле.
- Шапка: `crm_header`, `base.html`, адаптивные компоненты навигации.
  Общая кнопка звука регистрирует каналы; IndexedDB уже согласует вкладки.

## Этапы и критерии

1. [x] Состояние и контроллер: отдельные модели, адаптер Windows, межпроцессные
   блокировки; отсутствующий процесс восстанавливается, живой без heartbeat не дублируется.
2. [x] Heartbeat и штатный запуск: независимый поток для долгих задач, принятие
   существующих процессов, `all`, сохранение `-SiteOnly`, один владелец запуска.
3. [x] Читающий API и команды: безопасные поля для сотрудников, POST/CSRF/superuser,
   идемпотентность, три неудачи с сохранением между рестартами и подтверждение стабильности.
4. [x] Страница и предупреждение: четыре сервиса, реальные очереди, журнал;
   один звуковой канал с повторами через 10 минут и координацией вкладок.
5. [x] Проверки: подменённый OS-адаптер/API/принтер, права, гонки, сбои запуска,
   регрессия Django/CJS, check, миграции, браузер на изолированной БД.
6. [x] Документация, перегенерация технического справочника, итоговый отчёт.

Новые службы Windows, Redis/Celery, перенос на хостинг и удалённая печать не нужны.
Полностью завершившийся supervisor восстанавливается повторным штатным запуском CRM.
