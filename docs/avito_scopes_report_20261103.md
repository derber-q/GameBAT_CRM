## Выборка и склад

`pricing.avito_check_catalog.listed_products` выполняет одинаковый отбор CD/Tech:
через `Exists(AvitoListingConnection)` проверяет реальную связь, затем суммирует
`warehouse_stocks.quantity` и оставляет сумму > 0. Самого профиля недостаточно.
Партии реализации, товар в пути и будущие заказы не входят в физический остаток.
Разные склады складываются; `Exists` не размножает количество при соединениях.
Обе ручные цены предзагружаются, поэтому количество запросов не растёт на строку.

Архивные карточки с остатком сохраняют прежнее поведение: видны с пометкой,
оптовая и продажная цена доступны только для чтения. Ручной минимум остаётся
справочной записью. Автоматическая очередь `integrations.avito_check.queue()`
не переписана и по-прежнему исключает архив. Общий поиск учитывает тип товара,
название, артикул, ID, все `BarcodeRegistry`, а у дисков — CUSA/PPSA.
Сортировка имени общая, сортировка даты относится только к РФ; непроверенные
по РФ строки идут последними в обоих направлениях.

## Импортная себестоимость

Последний обычный `ProcurementPriceList` выбирается с `is_trip_addition=False`
по существующему порядку `-created_at, -id`. На весь экран выполняется одна
выборка версии и одна выборка необходимых полей её строк.

Ключ сопоставления — `(product_kind, product_id)`. Сумма берётся из существующего
`ProcurementPriceListItem.stock_unit_cost`: сохранённые `base_price_rub + delivery_rub`.
Исправленный поставщик и ручная AED уже учтены в сохранённых полях версии.
Наценка, цены покупателю, округление предоплаты и сегодняшний курс не подставляются.
Если товара в последней обычной версии нет либо самой версии нет — `—`.
Более старый прайс не используется, товар из таблицы не исчезает. Текущий `cost`
остаётся отдельной колонкой; расчёт показателя ничего не меняет в учёте.

## Модель, миграция и сохранение

`AvitoManualPrice.profile` теперь ForeignKey с `related_name=manual_prices`.
`scope` имеет допустимые значения `russia`, `rostov`; уникальна пара `(profile, scope)`.
Ограничение положительной цены сохранено. Отдельные дата и автор принадлежат
каждой строке scope.

Миграция `integrations.0011_avito_manual_price_scopes` добавляет scope с default
`russia`, меняет связь и создаёт ограничения. Прежние ID, суммы, даты и авторы
не обновляются. Копий старых цен для Ростова не создаётся. Это проверено отдельным
миграционным тестом на старой схеме. После появления двух географий нельзя
без подготовки возвращать старый код или OneToOne-миграцию: сначала нужен
согласованный план переноса данных либо восстановление снимка с соответствующим кодом.

`found-price/` проверяет права `pricing.view_pricing` + `pricing.change_retail_price`,
тип, ID, scope, положительный Decimal и точность. Сессия и CSRF штатные. Две формы
таблицы передают независимый `expected_recorded_at`. Расширение обязано передать
его вместе с `manual_queue=1`; дополнительно перепроверяются связь и физический запас.
Версия — исходный ISO с микросекундами, не локализованный текст даты.

В атомарной операции блокируется профиль (включая первое создание цены), затем
строка выбранного scope. SQLite повторяет целую транзакцию при краткой блокировке.
Несовпадение версии даёт HTTP 409 без записи. Другой scope не участвует в сравнении.
Цена, время, автор и аудит сохраняются вместе. Аудит содержит географию и прежние
значения. Сохранение той же суммы обновляет проверку только выбранной географии.

Если РФ дороже Ростова, ответ и строка показывают предупреждение из спецификации.
Сохранение разрешено, обе суммы остаются введёнными пользователем. Ручной минимум
не меняет `cost`, опт, цену Avito, остатки и очередь синхронизации; ReefAPI не вызывается.

## Поиск и предел географической проверки

Российский путь — `/all`, городской — `/rostov-na-donu`. Название города не
подставляется дополнительным словом в запрос. Для CD сохранены существующие
параметры состояния «Новое», формата «Физический», диска/картриджа; локализация
не ограничивается. Для Tech — название и «новый», без игровой категории/носителя.

Подтверждена корректность построения разных путей и сохранность параметров CD
в автоматических проверках. Существующие коды фильтров CD ранее сверялись с формой
Avito; в этой работе не менялись. **Живая строгость городской выдачи/радиуса не
подтверждена**: и `/all`, и `/rostov-na-donu` вернули HTTP 429 «Доступ ограничен:
проблема с IP». Свидетельство — локальный `geography_verification.json`.
Avito может расширять географию. В интерфейсе и инструкции явно предложено
проверить город/радиус на открытой странице. Неподтверждённые параметры не придуманы.
Тестовая выдача в Chromium не выдаётся за проверку географического поведения Avito.

## Расширение 1.7.0

Сохраняется одно MV3-расширение. Его права и список хостов не расширены.
`protocol.js` проверяет идентичность по `kind + productId + scope`;
в API это `kind + product_id + scope`. Ключ используется в очереди, начале из
нажатой кнопки, current/save/skip, проверке ответа CRM и поиске формы DOM.
CD и Tech с одинаковыми числовыми ID не смешиваются.

Порядок: товар 1 РФ → товар 1 Ростов → товар 2 РФ → товар 2 Ростов. Начало
соответствует нажатому этапу, с фильтрами и сортировкой исходной таблицы.
Панель показывает тип и географию; пустой Ростов не получает российскую цену.
Сохранение обновляет только нужные поле, дату и версию CRM; предупреждение пары
перерисовывается. Пропуск не пишет цену. Ошибка/конфликт не продвигает очередь.
Отдельные вкладки используют отдельные записи `chrome.storage.session`, команды
вкладки последовательны. Старые очереди и сообщения без scope отклоняются явно.

Авторизованная вкладка CRM остаётся мостом. Только она получает CSRF; на Avito
токен не передаётся. Оставлены проверки origin, разрешённых URL, frame и runtime ID,
обработка закрытой CRM и истёкшей сессии. Алгоритм выбора исходной цены, подавления
скидочной, зелёной/красной/жёлтой подсветки и блокировки перехода не изменён.
Поведение заказов/стикеров расширения не затронуто.
