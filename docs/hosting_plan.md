# Подготовка хостинга: контракт и этапы

Контракт пользователя от 31.10.2026 выполняется последовательно A–F.
Исходный HEAD: `main`, `ed6490e49ab107da2598ec27d3772f0f278da880`.
Дерево содержит пользовательские изменения и действующий мониторинг: они сохраняются.
Исходные файлы и status сохранены в игнорируемом `outputs/hosting_stage_a/baseline/`.
Живые процессы не останавливаются, рабочая БД не мигрируется и не копируется.

## A. Режимы и безопасная тестовая CRM

- [x] Явный серверный `GAMEBAT_ENV`; прежний запуск = `local_live`.
- [x] Независимые БД/файлы/ключи/сессии/пространства блокировок для `local_test`.
- [x] Запрет реальных интеграций, курсов, webhook, расширения и физической печати.
- [x] Отдельный запуск на другом loopback-порту, оранжевая шапка и постоянная метка.
- [x] Проверки смешения путей, внешних транспортов, SQLite, процессов, UI и регрессии.
- [x] Честная граница: production не допускается к запуску до проверенного этапа B;
  инфраструктурную изоляцию нельзя выдавать за проверенную без рабочего runtime.
- [x] Испытать закрытую контейнерную сеть без Python-guard: сборка, HTTP/браузер,
  запрет внешних TCP/DNS/LAN, права и сохранность данных при перезапуске проверены
  на Docker Engine 29.8.0. [Протокол испытаний](local_test_docker_acceptance_20261031.md).
  Исполнение кандидатов обновлений требует отдельного этапа C.

## Карта существующих точек расширения

`GameBAT_CRM/settings.py` сейчас выбирает рабочую SQLite и fallback-ключи в проекте.
Клиенты: Avito (`client.py`, фото в `services.py`), ReefAPI (`reef_api.py`),
Sheets (`google_sheets.py`), Яндекс (`client.py`, `documents.py`), курсы
(`core/services/{coinbase,rapira}.py`). Webhook — `yandex_market/webhooks.py`.
Физическая печать — `sales/label_printing.py`; состояния неизвестного результата
защищены `market_fulfillment.py` и в A не меняются. Расширение получает контекст
из `pricing/avito_check_views.py` и ссылки `manual_search_url`.

Мониторинг: `integrations/worker_*.py`, `run_worker_supervisor`, штатный
`start_localhost.ps1`, общий распознаватель `scripts/local_network.ps1`.
В A тестовые процессы используют другой entry point и никогда не вызывают
рабочий Windows-адаптер. Обычный запуск и его сигнатуры сохраняются.

Границы доверия: серверное окружение и пути конфигурации; HTTP не выбирает режим;
ключи/БД живой CRM недоступны разрешённым тестовым путям; перед внешним эффектом
проверяется центральная политика. Дополнительный низкоуровневый запрет стандартных
Python-транспортов не является ОС-песочницей для произвольного недоверенного кода.

## Последующие этапы

- B: PostgreSQL, транзакции, миграции на искусственных данных, Linux/HTTPS/файлы.
- C: Обновления GitHub, отдельный менеджер, проверенная установка и совместимый откат.
- D: Linux-адаптер и моделируемые процессы мониторинга с изоляцией окружений.
- E: Print Agent, безопасная очередь, HTTPS-origin и версии Opera GX.
- F: Полная регрессия и отчёт готовности; готовность хостинга только после VPS-испытаний.

Следующий рискованный этап допускается после проверок предыдущего. Этот проход
ограничен завершённым безопасным этапом A согласно разделу 25 контракта.

## Отдельное поручение 01.11.2026: подготовка ручных обновлений заранее

По прямому новому поручению подготовлены страница обновлений, очередь ограниченных
команд, отдельный Linux-менеджер и ручной workflow публикации. В local_live/local_test
кнопки только сообщают о доступности в production. Открытие страницы, idle менеджера,
перезапуск CRM и новые коммиты не запускают ни проверку GitHub, ни установку.
Это не снимает блокировку production этапа B и не подтверждает испытание на VPS.
Версии с изменёнными миграциями/зависимостями блокируются до отдельного проверенного
процесса миграций. [Контракт, реализация и ограничения](updates.md).
