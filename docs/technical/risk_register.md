# Подтверждённые ограничения перед крупной переработкой

Это карта для следующего этапа, а не разрешение изменить все перечисленные сценарии сразу.

| Приоритет | Наблюдение | Основание | Правило для следующего изменения |
| --- | --- | --- | --- |
| Высокий | Рабочие данные присутствуют в старой Git-истории | `git rev-list --objects --all`: прежние blob `db.sqlite3` | Новое игнорирование защищает будущие коммиты; историческую очистку планировать отдельно |
| Высокий | Завершённую продажу нельзя штатно редактировать формой постоплаты | `Sale.is_postpay_editable`, `sales.views.sale_edit` | Не отключать guard; проектировать отдельный сервис коррекции с аудитом, кассой, долгом и обратной операцией |
| Высокий | Возврат наличных привязан к исходному `sale_payment` | `cash.services.refund_sale_payment` | Дополнительный несвязанный deposit не гарантирует полный возврат при отмене |
| Высокий | API/печать — реальные внешние эффекты | integration worker, label print worker, on_commit queue | Моки в тестах; rollback CRM не отменяет внешний эффект |
| Высокий | SQLite сериализует writer и не даёт полноценных PostgreSQL row-locks | settings SQLite IMMEDIATE/WAL, retry, транзакции | Сохранять короткие транзакции, revision и ключи; не удалять их при рефакторинге |
| Средний | Большие сервисы концентрируют несколько сценариев | `supplies/services.py`, `price/excel.py`, `sales/services.py` | Разделять по стабильным контрактам после тестов; не совмещать перенос кода с изменением формул |
| Средний | Есть исторические поля/совместимость старых документов | миграции, legacy fulfillment, старые cost snapshots | Отсутствие кнопки не доказывает ненужность поля/ветки |
| Средний | Поля курс/цена имеют исторические имена | CurrencyRate и старые документы закупки | Проверять размерности: AED / USDT_AED × USDT_RUB; не менять старые финансовые снимки |
| Средний | Штатный запуск включает фоновые worker | `start_localhost.ps1` и `-SiteOnly` | UI-проверки запускать изолированно; наличие сайта не доказывает работу очереди |
| Средний | DOM Avito не контролируется проектом | расширение `cards.js`/`panel.js` | Fixtures разных карточек, проверка неоднозначности, права host ограничены |
| Средний | Звук зависит от autoplay, принтер — от ОС/драйвера | notification sound controls, Windows print adapter | Сохранённый статус/бейдж независим от слышимости; не обещать физическое наклеивание ярлыка по spooler |
| Низкий | Некоторые навигационные сценарии ограничены | `docs/development.md`, общая шапка/permissions | Перепроверять реальную роль и прямой URL; не снимать backend-защиту ради видимости |

## Что не признано мёртвым кодом

- Миграции, `AppConfig.ready`, signals, template tags, декораторы и management commands вызываются не только прямым импортом в Python.
- Старые ветки чтения документов могут обслуживать уже выданный Excel или сохранённую операцию.
- PNG-оригиналы, используемые `asset_pipeline.py`, необходимы для пересборки декоративных ресурсов.
- Тестовый/браузерный код и файл требований для Playwright — средства безопасности, а не пользовательские страницы.

Удалён прежний `price/supplier_ordering.py` с Ali-референсом: прямых/строковых импортов и ссылок в тестах/миграциях не обнаружено, генераторы используют `catalog/nomenclature_grouping.py`. Производственная сортировка Sony сохранена: `catalog/product_ordering.py` действительно её импортирует.

## Подтверждение перед рефакторингом

Минимальная единица проверки — весь изменяемый сценарий, включая повтор, конкурентное изменение, отмену и старые документы. Успешный общий suite не доказывает, что любой новый сценарий безопасен без собственных критериев приёмки. Отчёт этой подготовки содержит только реально выполненные проверки и их конечный результат.
