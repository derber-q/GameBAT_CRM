# Применение цифрового магазина 13.11.2026

Владелец отдельно разрешил проверить конфиденциальность, применить миграции,
перезапустить контейнер, затем включить магазин для самостоятельной проверки.
Полные тестовые наборы запускать запретил; Django/JS suites не запускались.

## Сохранность данных

Все действия с рабочей SQLite выполнялись Linux Python внутри Docker.
Предварительная согласованная копия проверена по integrity/FK, затем схема
применена к её отдельной копии служебным контейнером `--network none` без
сайта и worker. Отпечатки исходных колонок и строк 14 ключевых бизнес-таблиц
совпали до и после миграции; целостность и внешние ключи также проверены.

После штатной остановки `resource-crm-local` сделана окончательная копия:
`backups/before_digital_v2_final_20261113_154432/database.sqlite3`.
SHA-256: `12b6048a55bc42bda18d8f39ee66ba9f5567461451ad5b02f0db540178de9bf7`.
Размер 180731904 байта. Метаданные и отдельные копии семи файлов ключей рядом,
вне Git. Защищённая `backups/current_state_20261031.sqlite3` не изменялась.

## Применённая схема

* `digital_prices.0013`: характеристики v2, связи прежних карточек, общий лимит.
* `digital_sales.0008`: отдельный источник заказа `api_v2`.
* `digital_shop.0001`–`0005`: корзины, резервы, закупки, выдача, аудит.

Миграции выполнены служебным контейнером без сети при остановленной основной
CRM. Сразу после применения повторно сверены 14 бизнес-таблиц, integrity/FK;
новые выключатели оставались выключены. После запуска сайт отвечал HTTP 200,
закрытая панель перенаправляла анонимного посетителя на вход. Прямая компиляция
и рендер новой панели от штатного superuser завершились HTTP 200.

Дополнительно прошли Django `check`, проверка отсутствия новых миграций,
статический анализ F/E9, AST/компиляция шаблонов и проверка имён маршрутов.
Это **не** заявление о пройденных автоматических тестовых наборах или покупке.

## Конфиденциальность

Перепроверены публичные границы магазина, расчёта, результатов, чеков и PNG.
Используются разрешённые поля и клиентские суммы. Сырые ответы не транслируются;
неизвестный формат выдачи блокируется. Название с упоминанием поставщика или
закупочных данных заменяется целиком. API-номера не попадают в артикул Sale.
Административный просмотр закрытого результата требует отдельного права и аудита.
После включения отдельно проверены публичные DTO двух текущих персональных
каталогов и 212 подписей доступных товаров: закрытых полей/запрещённых упоминаний
не найдено. Проверка не выполняла сетевых вызовов и не отправляла сообщений.
Описание механизмов и ограничений: [контракт магазина](digital_shop_v2.md).

## Включение по отдельному поручению владельца

Магазин и подтверждение реальных закупок включены для двух уже привязанных
покупателей: «Подписки Играть» и «Подписки GNS». Другие группы автоматически
не подключались. Исполняющий пользователь — действующий superuser с правами
создания/завершения цифровых Sale. Любая новая закупка требует явного согласия
участника группы на окончательную цену в Telegram.

Выполнено обычное обновление API v2: 125 карточек, успешная первая попытка.
106 предложений прошли ограничения видимости для каждого покупателя.
Типы в ответе: ps, xbox, cprod, empty, steam_topup. Товаров code в этом ответе
не было. V1 fallback не используется; для кодов требуется доступность категории
в самом API v2. Старые карточки и их наценки сохранены для проверки/сопоставления.

Существующий механизм после успешного обновления отправил актуальные прайсы
обоим покупателям, обе рассылки завершены. Искусственные сообщения магазина,
пробные выдачи и реальные закупки агентом не выполнялись.

Команда для проверки пользователем: `/shop` в одной из двух подключённых групп.
Панель: `/crm/digital-shop/`, ссылка из страницы баланса цифровых продаж.
Кнопки выключения магазина и реальных закупок доступны в этой панели.

После перезапуска `check_worker_health` подтвердил рабочие циклы необходимых
обработчиков, связь ботов и доступность настроенных агентов печати. Docker
сообщил `healthy`. Физическая пробная печать не запускалась.
