# Таможенная опись рейса

На странице **Импорт → Заказы и рейсы → нужный рейс** находится кнопка
**«Таможенная опись»**. Адрес: `/crm/orders/trips/<номер>/customs/`.
Она открывает отдельный документ с десятью колонками исходного Excel GameBAT.
До прибытия количество берётся из текущих строк рейса `SupplierOrderBatchLine.quantity`.
После прибытия и сверки используется только `TripCostRow.actual_quantity`. Складские позиции,
добавленные в продажу отдельно от груза, в этот источник не входят.

## Когда можно подготовить документ

Опись можно составлять, сохранять и скачивать **до фактического прибытия**.
В этом режиме используются текущие положительные строки состава рейса; в интерфейсе
указано «Количество по составу рейса». Метка «Предварительная» не добавляется
ни на страницу, ни в Excel. Прибытие автоматически не создаётся и не подтверждается.

После подтверждённого `TripArrival.arrived_at` используются фактические количества;
для переключения на них требуется сверка всех заказов в `reviewed_orders`. Заказы покупателей и заказы на склад учитываются
одинаково. Финансовая финализация, создание продажи или приёмка прихода сами
по себе не являются условием подготовки описи. При несверенном составе редактор
покажет причину и не разрешит создание нового файла. Сначала завершите штатную
сверку фактических количеств каждого заказа. Нулевые источники остаются в истории
рейса, в экспорт не попадают.

Сумма источников показана как **«Количество по составу рейса»** до прибытия
или **«Фактически поступило»** после прибытия и сверки. Рядом находятся сумма
текущего документа, число строк, дата прибытия, версия прибытия и редакция описи.
Для каждой строки можно раскрыть список исходных товаров и фактических строк.

## Группы и начальные характеристики

Игры объединяются по явному правилу конкретной платформы из справочника
**«Таможенные правила»**. Правило задаёт тип носителя: диск или картридж.
PS4/PS5 — диски; Nintendo Switch/Switch 2 — картриджи. Неизвестная платформа
не определяется по подстроке названия товара: такие товары показаны отдельно
с предупреждением до настройки явной связи. Допустимо несколько разных кодов,
стран или материалов в одной платформе — они создадут отдельные строки.

Каждая модель техники выводится отдельно; одна модель в нескольких заказах
может объединяться при совпадении характеристик. Заказчик, поставщик и закупочная
цена не разделяют таможенную строку. Код, маркировка, страна, материал,
изготовитель, единица и описания входят в ключ группировки. Различающиеся
характеристики не подменяются одной общей строкой.

Начальные значения:

| Категория | Страна | Материал |
| --- | --- | --- |
| Техника | CHINA | МЕТАЛЛ / ПЛАСТИК |
| Диски PS4/PS5 | AUSTRIA | ПЛАСТИК |
| Картриджи Switch/Switch 2 | CHINA | ПЛАСТИК |

Единица — `ШТ`, номер N по умолчанию пустой. Страна `AUSTRIA` намеренно не
подменяется на `AUSTRALIA`. Эти значения являются исходными правилами,
а не подтверждением происхождения каждого изделия. Бренд техники показывается
как предварительный изготовитель и требует проверки. Для игр изготовитель
автоматически не угадывается. Код ТН ВЭД и маркировка без проверенного справочника
остаются пустыми. Штрихкоды CRM в маркировку автоматически не копируются.

Русское наименование берётся из исторического снимка заказа, затем из снимка
строки рейса, затем из карточки. Для настроенной группы игр используется её
групповое описание. Перевод берётся только из подтверждённых характеристик
товара или группы. Если его нет, русское описание копируется с явной отметкой
**«Английское описание не подтверждено»**. Внешние переводчики не вызываются.

## Редактирование и сохранение

Все десять полей документа доступны для исправления. Отметка
**«Характеристики проверены»** подтверждает непустые поля строки; изменение поля
снимает подтверждение этого поля. Пустое поле нельзя считать подтверждённым.
Код ТН ВЭД проверяется только по формату: десять цифр, включая ведущие нули.
Формат не доказывает юридическую правильность классификации.

**«Сохранить изменения»** создаёт новую редакцию только этого рейса. Имена
товаров, платформы, бренды, первоначальные заказы, поставщики, фактическое
прибытие, складские остатки и финансовые операции не изменяются. Ошибка
сохранения показывается без ухода со страницы и потери введённых значений.
Сервис повторно проверяет права, состав строк, количества и исходную редакцию.

Если нужно изменить количество только в документе, укажите целое неотрицательное
значение, поставьте **«Отличие подтверждено»** и заполните причину. Это требует
отдельного права подтверждения количества. История хранит первоначальный факт,
заявленное количество, причину, сотрудника и время подтверждения. Неизменённое
подтверждённое отличие можно сохранить повторно без нового согласования.
Без причины и подтверждения расхождение блокирует сохранение/экспорт.

## Характеристики для будущих рейсов

Обычное сохранение или скачивание не меняет справочники. Кнопки
**«Сохранить для товара»** и **«Сохранить для группы»** — отдельные действия
с отдельным правом и подтверждением. Для группы игр с несколькими источниками
можно выбрать конкретную карточку товара. Группа должна быть настроена явно.
Сохраняются только отмеченные проверенными непустые характеристики, без
количества. Сначала сохраните актуальную редакцию документа.

Приоритет при новой подготовке:

1. Ручные исправления конкретной редакции описи.
2. Подтверждённые индивидуальные характеристики товара.
3. Подтверждённые характеристики таможенной группы.
4. Начальные правила страны, материала и единицы.
5. Достоверный снимок наименования и предварительный бренд из CRM.

Группы настраиваются на `/crm/orders/customs/rules/`: выберите одну реальную
платформу игр либо одну категорию техники. Включение/отключение и изменение
правила действует при новой подготовке или обновлении, не переписывает
исторические редакции. Производитель и код не распространяются автоматически
на все товары без такого явного решения ответственного сотрудника.

## Устаревание, обновление и история

Документ сохраняет ревизии рейса/прибытия и SHA-256 тип источника (состав рейса или факт), отпечаток
источников: ID, товар, исходное и фактическое количество, снимок названия,
платформа/тип/бренд и список сверенных заказов. При отличии показывается:
**«Фактический состав рейса изменился после подготовки таможенной описи.
Необходимо обновить документ.»** Скачивание нового файла до обновления запрещено.

После подтверждения прибытия и сверки всех заказов сохранённая опись по составу
рейса становится устаревшей. Нажмите **«Обновить по фактическому составу»**.
До прибытия эта же кнопка обновляет документ по текущему составу рейса. Однозначно сопоставленные ручные
описания и характеристики переносятся, количества снова берутся из прибытия.
Прежнее отклонение количества не переносится автоматически. При разделении
или объединении неоднозначных строк новая редакция показывает предупреждение,
а прежние исправления доступны в истории. Новые товары заполняются правилами.
Если в группу добавился новый товар, перенесённые характеристики нужно проверить.

Каждое сохранение/обновление — отдельная редакция. Ссылка **«Редакция N»**
открывает её только для чтения. Исторический Excel — именно сохранённый файл,
с SHA-256 и временем формирования, а не пересчёт прошлого состояния по текущим
карточкам. Устаревшие исторические файлы доступны с правом скачивания и явно
обозначены как исторические. Одновременный старый редактор не перезаписывает
новую редакцию другого сотрудника.

## Экспорт

Проверьте предупреждения, подтвердите проверку перед скачиванием, затем нажмите
**«Скачать Excel»**. Редактор сохраняет введённые исправления новой редакцией
и отдаёт подготовленный файл. Пользователь с правом только скачивания получает
последнюю сохранённую актуальную редакцию без применения переданных правок.

Используется очищенная копия оригинального файла **«Опись груза GameBAT 03.11.xlsx»**:
`orders/resources/customs_manifest_template.xlsx`. На листе `ОПИСАНИЕ` сохранены
колонки A–J, строка заголовков 4, объединение `A5:J5` с `GRAND TOTAL`, оранжевая
тематическая заливка, шрифты, границы, ширины и настройки печати.
Случайные объединения C6:C7/C9:C14 примера удалены в очищенном ресурсе.
Тело динамическое: лишних строк другого рейса и технических листов нет.
Новые строки получают стиль исходного тела; длинные описания переносятся,
высота строки увеличивается в пределах ограничения Excel. Текстовые значения,
включая начинающиеся с `=`, `+`, `-`, `@`, записываются текстом, не формулой.
Числового итога в строку `GRAND TOTAL` не добавлено: сверка количества в CRM.

## Права

Все действия проверяются на сервере; существующие широкие права рейсов
не дают доступ к таможенным документам автоматически.

| Право | Назначение |
| --- | --- |
| `orders.view_customs_manifest` | Просмотр документа и его редакций |
| `orders.change_customs_manifest` | Подготовка, правка и обновление |
| `orders.download_customs_manifest` | Создание/скачивание XLSX |
| `orders.manage_customs_rules` | Группы и подтверждённые значения для будущего |
| `orders.approve_customs_quantity` | Подтверждение отклонения количества |

Для остальных действий требуется и право просмотра. Superuser имеет все права.
Пользовательские права выдаются администратором в штатном редакторе сотрудников.
Таможенная страница не показывает закупочные цены и реквизиты поставщиков.
Кнопка в карточке рейса видна с правом просмотра; сама карточка сохраняет
прежние требования к закрытым сведениям рейса.

## Техническое сопровождение

Миграция `orders.0012_customs_manifests` добавляет семь самостоятельных таблиц:
группы, индивидуальные характеристики, редакции, строки, источники, файлы,
события. Миграция `orders.0013_customs_before_arrival` добавляет режим состава рейса,
допускает отсутствие прибытия и даты прибытия, связывает источники со строками
рейса. Источники связаны с `TripCostRow` либо `SupplierOrderBatchLine`, CD/Tech и сохраняют собственные
снимки. SET_NULL не блокирует допустимое пересоздание источников прибытия;
исторические ID и количества остаются в описи. Файлы лежат в защищённом media
и включаются в штатную полную резервную копию как FileField.

`seed_customs_groups --actor-id <superuser>` выполняется только явно при установке:
создаёт отсутствующие группы для точных известных обозначений платформ,
при неоднозначности ничего не угадывает и требует ручной настройки.
Старые группы/товары/редакции не исправляет. Коды и изготовителей не назначает.

Основные модули: `orders/customs_models.py`, `customs_service.py`,
`customs_excel.py`, `customs_forms.py`, `customs_views.py`.
Подготовка ресурса: `scripts/prepare_customs_template.py`; исходную отправку
не коммитят. `customs_manifest_layout.json` хранит только оформление/заголовки
и хеш темы без коммерческих данных. Перед рабочей миграцией обязательны
согласованная копия SQLite и файлов/ключей, после — проверка прежних таблиц.
