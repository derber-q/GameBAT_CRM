# ReSOURCE Print Agent для Windows

Агент работает на компьютере, к которому подключён принтер этикеток. CRM может
работать в Docker или на удалённом сервере. Агент сам обращается к CRM; входящие
порты на компьютере магазина не нужны. Доступ к основной БД и ключам площадок
агенту не передаётся. На удалённом сервере обязателен HTTPS с действующим сертификатом.

## Установка

Распакуйте комплект в постоянный каталог. Установите Python 3.14 и Windows-драйвер
принтера. Запускайте команды под тем Windows-пользователем, которому доступен принтер.
Из каталога комплекта в PowerShell:

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r print_agent/requirements.txt
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup_print_agent.ps1 -ServerUrl https://crm.example.ru -PrinterName "Xprinter XP-365B"
```

В примере замените адрес на адрес своей CRM. Настройка создаёт приватный каталог
`%LOCALAPPDATA%\ReSOURCE\PrintAgent`. В `config.json` находится секрет агента:
не пересылайте этот файл и не добавляйте его в Git. `registration.json` содержит
только публичные параметры регистрации; его нужно передать администратору CRM.

На сервере после применения миграций администратор регистрирует агент:

```sh
python manage.py register_print_agent < registration.json
```

В окружении CRM задайте `GAMEBAT_PRINT_BACKEND=agent` и перезапустите сайт и
контроллер обработчиков. При нескольких зарегистрированных агентах явно задайте
`GAMEBAT_PRINT_AGENT_ID` UUID нужного агента. Один агент обслуживает один принтер.
Для текущей локальной CRM есть сокращённая настройка:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup_print_agent.ps1 -ServerUrl http://127.0.0.1:8000 -PrinterName "Xprinter XP-365B" -RegisterDocker resource-crm-local
```

HTTP разрешён только через loopback локального компьютера. Сетевой HTTP и
перенаправления запрещены. Для HTTPS проверяются сертификат и имя сервера.

## Запуск и остановка

```powershell
.venv\Scripts\python.exe -m print_agent --check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_print_agent.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_print_agent.ps1 -Stop
```

`--check` проверяет доступность принтера без печати. Запускатель открывает скрытый
процесс, повторный запуск не создаёт второй экземпляр. Остановка выполняется после
текущей операции. Агент нужно запускать после входа в Windows; автоматическая
задача входа установщиком не создаётся. Компьютер и принтер должны быть включены.

Состояние агента и принтера видно в CRM на странице «Обработчики». Серверный
обработчик печати запускается и восстанавливается контроллером CRM. Журналы агента
и его собственная SQLite находятся в приватном каталоге PrintAgent. Это отдельный
журнал доставки, а не копия основной БД. Сохраняйте его при обновлении агента:
он защищает от повторной отправки после сбоя. Файлы PDF в журнале не хранятся.

Если результат печати неизвестен, автоматический повтор и перевод заказа в
READY_TO_SHIP блокируются. Сотрудник с правами печати/продаж проверяет бумагу и
выбирает решение в CRM. Само попадание в очередь Windows не считается печатью:
нужно подтверждение драйвера. Отдельного датчика выхода бумаги агент не имеет.

## Перенос CRM и смена доступа

Перед переносом остановите прежний рабочий сайт и обработчики, перенесите
согласованную БД, медиа и ключи по процедуре CRM. Не запускайте две рабочие CRM
параллельно. При сохранённой БД UUID и хеш токена агента уже находятся на новом
сервере. На компьютере принтера остановите агент, повторите настройку с новым
HTTPS-адресом без `-Rotate` и запустите агент. Его локальный журнал сохраняется.

Чтобы сменить секрет, остановите агент, повторите настройку с `-Rotate`, передайте
новый `registration.json` администратору, повторите регистрацию и запустите агент.
Старый токен перестанет действовать. Для отзыва доступа на сервере:

```sh
python manage.py register_print_agent --disable UUID_АГЕНТА
```

После аварийной остановки новый экземпляр может ждать до 90 секунд, пока закончится
старая сессия. Задание с неизвестным результатом требует проверки сотрудника даже
после смены токена или сервера. Режим `local_test` запрещает настоящую печать.
Готовность конкретного VPS подтверждается отдельным испытанием на этом VPS.
