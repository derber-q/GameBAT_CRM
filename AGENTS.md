# Инструкции агенту GameBAT_CRM / ReSOURCE

Пояснения пользователю, новая документация и содержательные комментарии пишутся по-русски. Идентификаторы кода и сторонних API сохраняют существующий стиль.

## Перед работой

Прочитать `README.md`, `docs/architecture.md`, `docs/operations.md`, `docs/development.md`; проверить `git status --short`. Изучить модели, сервисы, views, формы, URL, шаблоны и тесты нужного сценария. Старые отчёты в `docs/` фиксируют историческое состояние: сверять их с кодом.

Работать в существующем проекте и сохранять пользовательские изменения. Не повторять старые импорты и очистки из истории чата. Не обнулять БД, удалять историю, товары, связи Avito, группы или остатки без конкретного поручения.

## Правила данных

- Физический остаток — `CDWarehouseStock`/`TechWarehouseStock`; общего складского количества в карточке нет.
- `quantity_on_consignment` — производная сумма всех партий площадок, а не независимый запас. После изменения учётной логики запускать `verify_inventory`.
- Различать склад, реализацию, товар в пути и глобальную собственность для себестоимости.
- Деньги считать `Decimal`, клиентские проверки — в целых копейках/`BigInt`, не `float`.
- Использовать существующие сервисы, аудит и транзакции. Прямой SQL и `QuerySet.update()` обходят `save()` и сигналы Avito; массовые коррекции требуют разрешения на данные и отдельной проверки результата.
- Не объединять партии реализации с разными вознаграждениями. Для возврата/продажи партии использовать `stock_id`.
- Удаление карточки, отмена продажи и отмена прихода — разные операции; сначала изучать соответствующий сервис.
- Не пересчитывать старые продажи по текущей цене или себестоимости. Сохранять снимки строк и честно обрабатывать отсутствие старого снимка.
- Наценка от опта — порог предупреждения, не формула автозаполнения цены.
- Штрихкод — строка с возможными ведущими нулями. Искать по всему `BarcodeRegistry`, а не только по совместимому свойству `.barcode`.

## Права и интерфейс

Скрытие кнопки не заменяет backend-проверку. Использовать текущие permissions и декораторы. Пользователи и `stuf` защищены `superuser_required`; одного `accounts.view_user` сейчас недостаточно.

Переиспользовать `base.html`, `nav-dropdown`, панели, таблицы, диалоги ReSOURCE. Сворачивание использует `data-collapse-toggle`, уникальный `aria-controls`, `collapsible-content`. У фильтров бывают отсутствующие поля: не обращаться к `null.value`.

После изменения общей статики обновлять версию в шаблоне и связанные проверки. Сохранять AJAX-сохранение цен. Сканер подключается через `window.GameBAT.registerGlobalBarcodeHandler` и не должен мешать обычному вводу.

## Запуск и Avito

Avito — реальный внешний сервис. `run_integration_worker`, синхронизация в интерфейсе и `verify_avito_sync --fix` могут менять объявления. Не запускать их только ради проверки документации/интерфейса. Тесты должны подменять API и не использовать рабочие ключи.

Сайт и worker — разные процессы. `--noreload` требует перезапуска после изменения Python/кешированных шаблонов. Проверять путь и команду процесса перед остановкой, не завершать все Python-процессы. Фоновые окна запускать скрыто. Для сети разрешать конкретный LAN IP через `DJANGO_ALLOWED_HOSTS`.

## Проверки и Git

Проверки выбирать по риску; для контрольной точки и по требованию пользователя — полный Django suite, все `test_*.cjs`, `check`, проверка миграций. Диагностику рабочей БД проводить отдельно от тестов. Команды — в `docs/operations.md`.

Не писать «все тесты прошли» без итогового результата процесса. Ожидаемые ошибки негативных тестов в журнале не равны сбою suite: смотреть `OK`/`FAILED` и код возврата. Тест шаблона не заменяет ручную проверку наведения в браузере.

Перед опасной правкой БД создавать согласованную SQLite-копию. Секреты и медиа резервировать отдельно от Git. Откат CRM не откатывает Avito.

Коммит и push — только по прямой просьбе пользователя. Разовое разрешение не распространяется на будущие изменения. Перед отправкой проверить состав файлов, миграции, тесты и отсутствие секретов. Не добавлять `backups/`, `outputs/`, `.venv`, `node_modules`, ключи и `.env`. Не использовать force push и разрушительный reset. В финале указать результаты, хеш, ветку и результат push.
